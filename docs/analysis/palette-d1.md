# 팔레트 프레임 처리의 D1 결과

원본 프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
여기서 CPU4718/479e/4c40/504c/5728/7196은 고정 프로그램 영역이며 같은 복호화 ROM 오프셋이다. 팔레트 데이터는 기존 버전 있는 MS5P 리소스를 C++ 로더로 읽는다. 진단 이미지에서 색을 역추출하지 않는다.

`step_palette_frame`과 `prepare_palettes`에 선택적 입출력 `std::uint32_t* d1`을 추가했다. 기존 RAM·포트 계약과 호출법을 유지하면서 필요할 때 원본 D1을 전달할 수 있다. 실패 시 D1도 RAM·포트와 함께 보존한다. 다른 scratch 레지스터나 SR/CCR 전체를 반환하는 API는 아니다.

## 원본 명령에서 확인한 규칙

5728의 타이머가0이면 타이머 경로는 D1을 쓰지 않는다. 타이머가 활성일 때5734는 이전RAM107dc4.byte를D1.byte에 읽고,5778은 갱신된 같은 바이트를 뺀다. 따라서 하위8비트는 이전−이후 modulo256이고 상위24비트는 입력 그대로다. 전체 dirty 표시 루프와 pending 검사에는 D1 쓰기가 없다.

7196은 슬롯0..255를 순서대로 처리한다. dirty 슬롯마다 호출하는 helper에 따라 D1 결과가 다르다.

| helper | 동작 | 반환 D1 |
|---|---|---|
| 4718 | 선택 팔레트 복사 | 입력 그대로 |
| 479e | 색 보정만 적용 | 하위16비트=마지막 색15의 보정된 중간 채널0..31 |
| 4c40 | 두 팔레트 혼합 | 하위16비트=마지막 RGB555 색×2 |
| 504c | 혼합 후 색 보정 | 하위16비트=마지막 보정 RGB555 색×2 |

모든 변환 helper는 상위16비트를 보존한다. 혼합 weight0 또는31이상은 선택된 팔레트의 복사/색 보정으로 분기하므로 혼합 인덱스를 남기지 않는다. 같은 ID도 복사/색 보정 경로다. effects가 활성이어도 슬롯 flag2가 있으면 색 보정은 생략된다. 뒤쪽 슬롯이 단순 복사이면 앞선 변환의D1이 그대로 남는다.

최종 반복의 실제 명령도 확인했다. 479e의 마지막 색 처리는4bee..4c38이며 D1은 중간 채널에만 사용된다. 4c40의 마지막4ca4 대응은5040, 504c의 마지막 대응은571c의 `add.w d1,d1`이다. 그 뒤A2/A4를 복구하고RTS하므로 이 값이 유지된다.

```sh
build/step_palette_frame --d1 0x12345678 INPUT_RAM INPUT_MS5P OUTPUT_RAM OUTPUT_PORTS
```

stdout JSON의 `d1`은 성공한 최종 unsigned32 값이다. 기존 옵션 없는 호출은 출력 형식과 동작을 유지한다.

이 변화는 f46의 팔레트 호출 이후 값을 다음 입력의 style로 연결하는 데 필요하다. f4c 대기와 실제 메인 문맥 연결은 후속 작업이며 현재 API 추가만으로 전체 메인 루프 실행이 완료된 것은 아니다.

## 원본 비교 결과

`.venv/bin/python tools/verify_palette_d1.py`에서566조건(독립560, 동일 출력 RAM/D1을 이어받은6프레임)과 오류14조건을 통과했다. 전체RAM,32비트D1, 시간순 MMIO43,684개를 비교했다. 네 가지 실제 helper 진입을 code hook으로 확인했고 D1 기대값은 원본 실행에서 직접 읽었다.

사용 MS5P는 ROM으로 다시 추출한 레코드와 전체 파일을 비교했다. 실제 두 팔레트203/87a를 양방향 혼합하여 감소하는 채널을 포함했다. timer0/1/2/255, pending/효과 면제, weight0/1/15/30/31/255, 여러dirty슬롯과 마지막 단순복사 경로를 확인했다. 원본 고정 코드와 데이터 bank는 PVC 제어 영역을 제외하고 불변이다.
