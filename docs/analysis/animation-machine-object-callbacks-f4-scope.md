# 객체 node callback(F4) 범위 분석: 미연결 callback·공유 객체 core·seed 해제 곡선(구현 전 계획)

**상태: 읽기 전용 범위 분석에 메인 결정을 반영했다. 구현·검증 기록이 아니며 계약도 아니다.**

메인 결정(Claude Opus 5.5): "결정 필요" 1~8을 작업자 권고대로 채택한다.
1. RNG 초기화: seed 준비 단계로 native `49a1a`(D0=0)를 실행한 선언 seed 집합을 새 관측으로 만든다(기존 seed는 그대로 두고 변형 집합으로 추가). R01~R15는 U10 뒤.
2. `c00468`(BIOS CARD, `48090` 경로)은 frame pass에서 선언 "bios-card" 대기로 두고 fade_card 계약의 재개(PC=`c37c`, A7 순변화 없음, BYTE `10fdc6`=응답)를 재사용한다. 기본 응답 `80`, 변형 `00`. BIOS 실행 주장은 하지 않는다.
3. block 시작은 정적 디코드 기준(Unicorn TB 분할 아님). 4. terrain 점프 표는 index 상한을 정적으로 확정하고 전체를 옮긴다(상한 미확정이면 F1 결정 3 정책). 5. 단위는 함수 본문 전체, 실행되지 않는 callee는 경계. 6. TRAP #f 23곳은 checked 경계. 7. PVC bank 4는 guard. 8. 순서 U01~U07 → 결정 1·2 → U08~U16(R01~R02는 U10 뒤) → U17~.
- 진행 방식: 단위마다 Opus 작업자가 계약 절(바이트 근거·block 목록·carry·경계)과 C++ core를 함께 작성하고, Sonnet/high 관측과 Sonnet/medium 검증을 이어 붙인다.

Claude Opus 5.5 / high 읽기 전용 분석 작업자가 작성했다. canonical BE ROM `extracted/program/maincpu.decrypted.be.bin`(8 MiB, SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`)을 썼다. fixed 영역은 CPU 주소와 file offset이 같다. 이 문서의 코드 주소는 모두 fixed `<100000`이다. banked 코드는 실행되지 않았다(아래 [F]). 작업 전후에 ROM SHA256과 mtime이 변하지 않았음을 확인했다.

- 기준 실행부: worktree `/Users/start/Workspce/metalslug-input` HEAD `55261ac`(F2 scheduler shell WIP). `engine/src/animation_machine.cpp` SHA256 `90ac84f0a1e6f720d78ef772d10e6b4729b86a8c992bd6a729385685afcfa5b7`, routing 규칙 34개. "연결됨(routed)"은 이 routing 조건(`stage_event_ops_trap` 8 PC 제외)을 PC마다 평가한 값이다.
- native 기준: `artifacts/animation_machine_scheduler_native/observation.json` SHA256 `c330e597f9585c2595006239be49ab0bcb029f4b5fed5c70ebf872fe91a2b4ff`와 그 `seeds/seed_NNNN.json.gz`. seed 입력은 `artifacts/stage_entry_body/observation.json` SHA256 `1f65100f1fedc36b4999543c720814dc6f9eb4bf634f3af3439aa68d70e31207`이다. 자연 seed 137개, guard-release 5개다.
- 표기: [F]=원본 바이트, 기록 산출물, 또는 작업자 scratch Unicorn 재생에서 확인한 사실. [I]=추론. [U]=미확인.
  - "자연"은 F2 결정 2~4의 **선언 프레임 패스 모델**을 Unicorn으로 돌린 결과다. 게임 자연 실행이 아니다. BIOS 실행, 자연 IRQ, 자연 scheduler 진행은 주장하지 않는다.

## 요약

- [F] **재현.** scratch 재생은 native 관측 도구 `tools/observe_animation_machine_scheduler.py`(SHA256 `62bb23ff…c01c`)의 `SeedRun`을 수정 없이 in-process로 불러 TB 시작 hook만 더했다. 142 seed 모두 pass별 끝 상태 SHA가 native 기록과 같았다. 메인이 준 "첫 미연결 callback" 분포(37 callback: `dbdb6` 13, `b4d7e` 12, `e5120` 11, 4개×4, 2개×30)도 정확히 재현했다.
- [F] **미연결 실행 규모.** 기록 구간(120 frame, 또는 native 끝)에서 실행되는 미연결 block 시작(TB 시작 기준)은 2,920개다. node callback은 257개다.
  - 이를 덮는 함수(호출 대상·callback·연속 callback·동적 간접 대상 단위의 intra-procedural 본문, 미실행 callee는 경계) 합계는 **624 함수, 6,463 block 시작**이다.
  - 아래 결정 1(RNG 초기화 선언)을 적용하면 **773 함수, 7,853 block 시작**이다.
  - 정적 전이 closure(모든 호출·연속·자식 callback 추종)는 15,354 block 시작으로 훨씬 크다.
- [F] **frame 지평.** 기록 지평을 120에서 400 frame으로 늘려도 새 미연결 block은 0개였다. 필요 코드는 120 frame 안에서 포화한다.
  - 대신 거의 모든 seed가 frame 220/240/244에 stage 종료 페이드 `48090`→`c364`→BIOS `c00468`(CARD)에 닿는다. 기본 seed에서는 87개, RNG 초기화 seed에서는 128개다.
- [F] **두 native 종료 원인이 seed 해제를 지배한다.**
  - (1) 142개 seed RAM 전부에서 RNG 포인터 LONG `10d722`=0이고 고리 `10d6b4..10d722`도 0이다. 그래서 41개 seed가 첫 RNG 호출(`49a58`→`49a80 SUB.W D0,(A3)`, A3=`30`)의 ROM 쓰기로 frame 0/1/35에 끝난다.
  - (2) 카드 BIOS `c00468` 경계다.
  - 둘 다 **새 block 없이** 선언으로 풀 수 있다(결정 1·2). card 응답을 선언 재개하면 18개 seed(현재 실행 가능 16+frame 0의 2)는 지금 실행부만으로 400 frame을 완주한다.
- [F] **공유 객체 core**(C1 palette 참조 `8ebe`/`c6a96`, C2 객체 helper `1aa3a`~`1abda`, C3 수학 `49098`~`497b6`, C4 이동 `4b50c`~`4c29a`, C5·C6 지형 충돌 `43ea4`~`47288`+`18be8`)는 12 seed 이상이 쓰는 함수만 세어 **741 block**이다.
  - 지형의 `JMP d(PC,D7.W)` 표 5개를 전부 옮기면 약 312 block이 더 든다.
  - core만으로는 seed가 풀리지 않는다. callback 계열과 함께 들어가야 한다.
- 제안: 함수 단위 greedy(새 block당 해제 seed 수)를 ≤~200 block 단위로 묶은 **U01~U47(6,463 block)**, 결정 1을 채택할 때 추가하는 **R01~R15(1,390 block)**.
  - 첫 7단위(697 block)로 완주 seed가 25→60개가 된다. 결정 2 적용 시 실행 frame 합은 9,601→21,207이다.

## 측정 방법

- [F] 재생은 F2 프레임 패스 모델 그대로다.
  - 시작 상태: PC=`2ac2`, A6=`1008e4`, A7=`1ff000`, LONG `104ca4` 선언 쓰기.
  - stop: frame head `e4a`/`e74`.
  - 선언 대기: sound, sprite, palette gate.
- [F] 기록 지평은 native 기록과 같다. 120 frame이고, 실행 가능 seed는 400 frame이다. 추가 변형:
  - 지평 400(`base400`).
  - RNG 초기화 선언(`rng`, `rng400`).
  - card 응답 선언 재개(`base80` `rng80`, 응답 `80`, 400 frame).
  - 변형 결과는 native 산출물에 없는 scratch 측정이다.
- [F] 미연결 판정은 HEAD routing 범위 밖의 TB 시작이다.
  - 실행 가능 22 seed에서 나온 routing 밖 TB 시작 12개는 기존 실행부의 묶인 분기 내부로 보고 제외했다(`8c2a` `8c34` `8c42` `8c4c` `8c5a` `8c64` `8c82` `8c86` `8ca0` `8ca6` `8cb0` `47fe0`). 이 규칙으로 메인 분포가 정확히 재현됐다.
  - [U] 아직 실행 가능하지 않은 seed에만 나오는 기존 실행부 내부 TB가 있으면 소수 과대 계산이다. [I] routing 범위 ±`40` 안의 미연결 TB 103개를 목록으로 검토했고, 별도 routine 진입·분기 대상으로 보였다(전수 디코드 확인은 아님).
- [F] block 시작 수는 capstone M68000 정적 디코드로 셌다. 기준은 진입, 분기 대상, 조건분기·DBcc fall-through, JSR/BSR 복귀점이고 routing 안 PC에서 멈춘다.
  - "함수"는 JSR/BSR 대상, node callback, `MOVE.L #imm,(A6)` 연속 callback, `28ae` 자식 callback, 그리고 정적으로 닿지 않는 동적 TB 시작(136개)의 intra-procedural 본문이다.
  - seed의 필요 block은 그 seed가 실행한 미연결 TB 시작을 포함하는 함수(가장 가까운 앞 진입) 본문의 합집합이다.
  - [I] 실행되지 않은 callee는 실행부 없는 경계(`unsupported animation machine PC`)로 남긴다는 가정이다. 기존 U1~U7·F1x와 같은 방식이다.
- [F] 136개 동적 고아 TB에는 두 종류가 있다.
  - (a) 지형 `JMP d(PC,D7.W)` 표의 `BRA` 대상(`448be` `448ca` `4499e` `449a2` 등).
  - (b) Unicorn TB 분할 인공물(예: `8fe0` `8fe4` `8fe8` `8fec` `8fee` `8ff2`는 `8ebe` 본문 직선 구간).
  - 따라서 계약의 block 시작은 TB가 아니라 정적 디코드로 정해야 한다(결정 3).
- seed 해제는 seed의 모든 기록 pass(마지막 정지 pass 포함)가 구현 집합 안일 때 "완주"로 센다. "실행 frame"은 앞에서부터 연속으로 구현 집합 안인 pass 수의 합이다.

## 48090 / c00468 경계

- [F] 경로. stage controller(`100b30`)의 페이드 상태 `4804e`(`8c16` 페이드, `7a`=`80` frame) → `48074`(두 번째 페이드, `7a`=`20`) → `48090`(`7a` 감소) → `4809a JSR caf0`(화면 reset, 기존 screen 실행부) → `480a0 JSR c364` → `c364` `MOVE.L A6,-(A7)`; BYTE `10fdc4`=1; WORD `10fdce`=`0268`; `c376 JSR c00468`.
  - 복귀 `c37c`는 A6 pop, A5=`108000`, `CMPI.B #80,7dc6(A5)`(BYTE `10fdc6`)를 한다. 같으면 `c3b8 MOVE.B #ff,62(A6)`다. 다르면 `62(A6)`=0, 자식 `c250`(`28ae`), 자식 `76`=`c188`, `7a`=`7c`=4를 쓴다. 이어 `480a6`이 callback을 `480ac`로 바꾼다. `480ac`는 `62(A6)`≠0이면 `480b6 JMP 2a00`(자기 삭제)다.
  - [F] `c364..c3c0`은 기존 fade_card 실행부 범위다.
- [F] `c00468`은 Neo Geo BIOS의 CARD 진입이다. 카드 저장 단위(`bd26`)도 같은 진입을 명령 4/3으로 부른다.
  - [I] `0268`은 이 게임의 NGH 번호, `10fdc4`는 명령, `10fdc6`은 응답 BYTE다.
  - [U] 명령 1의 정확한 의미와 응답 값의 의미.
- [F] 이미 선언된 재개가 있다. fade_card 계약 6·"BIOS 뒤 재개"는 PC=`c37c`, A7+=4, BYTE `10fdc6` 하나만 바꾸고 carry Unknown으로 둔다. card_menu_save 계약도 같은 형식이다.
  - 그러나 F2 프레임 패스는 stop PC가 frame head 하나뿐이다. 그래서 패스 중 `c00468`은 checked 오류와 패스 rollback이 된다. 현재 native 기록은 이 지점을 `bios-boundary`로 끝낸다.
- [F] scratch 측정. `c376`에서 위 선언 재개를 적용했다(JSR을 실행하지 않고 PC=`c37c`. A7은 push+BIOS RTS pop의 순효과로 불변, BYTE `10fdc6`=응답). 결과:
  - 응답 `80`: 18 seed(4 5 10 11 48 49 50 51 64~67 78 79 86 87, frame 0의 94 95) 모두 400 frame 완주. 재개 뒤 미연결 block은 0개다. stage controller는 `480b6`에서 자기 삭제한다. 이후 패스는 `270e` idle뿐이다(94·95는 event node `e9176`도 있다).
  - 응답 `00`: 같은 18 seed 400 frame 완주, 미연결 0. 자식 `c250`→`c266`→`c286`(20회)→`c2ba`(134~311회)·`c2e0`(94·95)이 이어진다. 모두 기존 card child·card menu 실행부 범위다. `76(A0)`=`c188`(미연결)은 400 frame 안에 실행되지 않았다.
  - RNG 초기화+`80` 재개 변형: 128 seed가 경계를 지나 400 frame까지 갔다. 재개 뒤 실행된 미연결 block은 0개다.
  - [U] 경계 뒤 미연결 코드가 없는 원인(stage 종료 전에 객체 node가 정리되는지). 측정상으로는 경계 뒤 새 코드가 필요 없다.
- [I] 원본에서 응답 `80` 뒤 controller `c66a`가 `100b30` 비활성을 보고 `c69a` 종료(BIOS `c00444`)로 가는 흐름은 F2 결정 3의 선언 skip 때문에 실행되지 않는다. 경계 뒤 frame은 "idle 패스"로만 의미가 있다.
