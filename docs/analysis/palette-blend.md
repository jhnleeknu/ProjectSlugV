# 원본 팔레트 혼합4c40

프로그램 SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 아래 고정 ROM 주소는 CPU 주소와 파일 오프셋이 같다.

4c40은 D0.W=0이면 첫 팔레트의 일반변환4718로 분기한다. 그 외에는 A0/A1을 교환하고 unsigned D0.W>=31이면 두 번째를 변환한다. 준비7196은 node+e byte를 zero-extend하므로 계수 범위는0..255다.

계수1..30에서 각 원본 색word를 5비트 성분으로 나누고, 첫 성분a와 두 번째b의 차이로 ROM `3f78 + weight*64 + (b-a)`를 조회한다. MOVE.B가 차이 레지스터의 하위byte만 바꾸는 효과를 포함한 독립 모델로 원본을 비교했다. 15비트 원본 색의 경우 최종 재조립에서 그 상위 잔여비트가 소거된다. 1890개 조회값(30×63)은 모두 `trunc_toward_zero((b-a)*weight/31)`의 하위byte와 같다. 따라서 성분 계산은 `a + (b-a)*weight/31`로 정확하게 표현된다.

혼합된15비트값v는 signed16(v*2)를 A3 lookup base에 더해 하드웨어word로 변환한다. ROM의32768개 해당 조회값을 전부 검사했으며 다음 비트배치와 일치한다.

```
((v&1)<<12) | ((v&0x20)<<8) | ((v&0x400)<<4)
| ((v>>1)&15) | ((v>>2)&0xf0) | ((v>>3)&0xf00)
```

C++는 MS5P의 source_words를 혼합하고 이 검증된 비트배치로 변환한다. 계수0/31이상과 두ID가 같은 경우에는 해당 MS5P hardware_words를 사용한다. 끝점은 실제로 읽는 한 리소스만 요구한다. 중간 혼합에서 원본 bit15가 설정된 색은 아직 검증범위 밖이므로 오류를 반환한다. 활성 효과가 있고 node bit1 우회가 없으면 기존처럼 미지원이며, 504c 효과혼합도 남아 있다.

검증:

- `tools/analyze_palette_blend.py`: 고정 seed의64개 팔레트쌍×계수0..31,255=2112조건. 원본4c40 전체RAM과 A2/A4 보존 일치. 조회표1890개와 색변환32768개 전수 확인.
- `tools/verify_palette_blend.py`: 실제 initializer ID5개의 순서 있는 서로 다른20쌍×33계수=660조건. 원본7196 전체RAM과 C++ MS5P 준비 결과 일치. 일반/효과우회 경로 포함.
- `make all test`: 전체검사 통과. 끝점 리소스 선택, 중간값 누락, bit15 거부와 rollback을 추가 확인.

이 분석은 일반 혼합 계산이다. 게임에서 각 오브젝트가 혼합 계수를 언제 갱신하는지, 전체 효과·프레임 타이밍을 복원한 것은 아니다.
