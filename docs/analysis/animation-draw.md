# 애니메이션 표시 명령에서 큐 생성기로의 연결

프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
아래 주소는 고정 ROM 파일 오프셋과 CPU 주소가 같다.

## 확인한 제어 흐름

0x49fc6은 오브젝트(A6)+26의 상태를 A0로 잡고 저장된 명령 포인터를 읽는다.0x49ffe는 한 byte를 읽어44보다 작은지 확인한 뒤0x4a022 상대 분기 표로 이동한다. 표의 유효 명령 값은4byte 간격이며, opcode04가0x4a104를 거쳐0x4a10c를 호출한다. 단순히0..43의 모든 byte가 유효한 명령이라는 뜻은 아니다.

0x4a10c는 opcode 다음의7byte를 읽는다: 제어 byte, X byte, Y byte, BE32 리소스 값.0x4a1fa에서 기존에 복원한0xcd58 큐 생성기를 호출한다. A1은7byte 전진한다. 원본은 호출 전 bank0으로 전환하고 이전 bank shadow를 스택에 보관했다가 호출 후 복원한다.

## 생성기 인자 변환

- X/Y byte를 signed8로 확장하고2배 한다. 제어bit1이 X의 추가1, bit0이 Y의 추가1이다.
- 오브젝트+12의long style을 읽는다. style bit0/1로 X/Y를 부호 반전한다.
- 오브젝트+42/+46 word를 더하고+53 byte의bit0/1에 따라 X/Y에서1을 뺀다. 최종 low16 두 개를 D0의상위/하위에 넣는다.
- 제어bit2/3은 style bit0/1과XOR한다. 따라서 상대 좌표 반전에 쓰는 기존 style과 최종 타일 반전에 쓰는 합성 style의 적용 순서를 바꾸면 안 된다.
- 제어 상위nibble은 팔레트 선택이다.10이상이면10을 빼고 style bit2를 토글한다. 이어5이상이면5를 빼고 일반 팔레트 선택으로 간다.
- 원래 선택값이 해당 단계에서5미만이고 오브젝트+16 word의low byte가bit0=1,bit7=0이면 그 word의high byte를 팔레트로 쓴다. 이외에는 선택값0..3일 때 오브젝트+19..1c의byte를 style의팔레트 byte로 넣는다. 선택값4이상은 기존 팔레트를 유지한다.
- D5는 오브젝트+1e word(정렬 키), D7은 읽은 리소스long에 오브젝트+20 word를OR한 값이다.

0x4a11a의7ff800 특수값, 상태+4의음수byte, 오브젝트+61 bit3과global10000f bit0 조합은 조기 반환 경로다. 초기 분석은 실제 제출되는 경로에 한정했고, 아래 C++ 통합 단계에서 조기 반환도 실행 비교했다.

## 실행 증거

`.venv/bin/python tools/analyze_animation_draw.py`

256제어byte ×4기존반전 ×3팔레트word =3072조건에서 원본0x4a10c를 실행하고0xcd58 진입 직전에 중단했다. Python 의미 모델의 D0/D1/D5/D7 및A1 전진이 모두 일치했다. signed 좌표와low16 wrap, 팔레트 우선순위, 부모 소수부 carry 보정이 포함된다.

이것은 표시 명령 인자 변환 검증이다. 애니메이션 프레임 대기·명령 흐름·실제 스크립트 추출·자연 게임 호출·전체 큐 후속 실행을 이번 검사에서 증명하지 않는다. 아래 C++ 통합 단계에서 이 규칙을 구현하고 기존 MS5C 큐 경로까지 연결했다.

## C++ 변환기와 연속 실행

`decode_animation_draw`는64KiB RAM, 오브젝트 RAM offset,7byte operand로부터 skipped 및 D0/D1/D5/D7을 만든다. RAM과 입력은 변경하지 않으며 잘못된 길이나 범위는 결과를 보존하고 실패한다. skipped 결과의 register0은 C++ 인터페이스의 명시적 표현이며 원본 반환 register값을 복원했다는 뜻이 아니다. A1 전진과 명령 포인터 관리는 호출자의 책임이다.

`analyze_animation_draw.py --cpp`가3072개 제출 경로와32개 특수ID/대기/깜박임 조합을 원본·C++와 비교한다. 원본 생략 분기에서도 A1이7전진하고 함수가 반환하는지 확인한다.

`verify_sprite_pipeline.py --blocks --flips --animation`은 원본4a10c를 생성기 호출과 bank 복원을 포함해 끝까지 실행한다. C++에서는 변환 결과를 `submit_sprite`에 전달하고 이어 기존 준비·갱신과 MS5C 로더를 실행한다. 네 연속 프레임, 방향과ring 시작점4조합,124제출·32단계의 전체RAM·비디오 출력을 비교한다. `--disabled-pool`은 비활성 영역을 포함한다. 제어byte의 다양한 좌표·팔레트 조합은 앞의3072조건이 담당하고, 이 연속 경로의operand 좌표는0으로 고정해 상태 전달을 검사한다.

명령 스트림의 프레임 대기와 분기 interpreter, 실제 스크립트 추출은 여전히 다음 단계다.
