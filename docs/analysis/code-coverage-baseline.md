# 정적 코드 커버리지 기준선

프로그램 ROM에서 정적으로 발견되는 코드 중 `engine/src/animation_machine.cpp`가 라우팅하는 PC 범위가 차지하는 비율의 기준선이다. 자동 역어셈블·정적 탐색 결과는 후보 집합이며 분석 완료가 아니다. 표기: [F] 사실(ROM·코드에서 직접 확인), [I] 추론, [U] 미확인.

## 입력 (이번 실행)
- [F] ROM `extracted/program/maincpu.decrypted.be.bin`, SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`, 8,388,608바이트. 고정 영역 CPU 0..0xfffff는 파일 오프셋과 같다.
- [F] `engine/src/animation_machine.cpp` SHA256 `c7318132fcdfd288c12a58ab7e51c03e2920b46d7e939103bd917d72ca8caad2`.
- [F] 도구 `tools/measure_code_coverage.py`의 SHA256은 보고서 `inputs.tool`에 기록된다(도구를 고치면 값이 바뀐다). 디코더 Capstone 5.0.6 M68K(68000). 보고서는 결정적이다(같은 입력에서 SHA 동일을 두 번 확인).

## 방법
1. [F] 명령어 크기·유효성은 Capstone, 제어 흐름은 이 도구가 opcode 비트로 분류한다. `dc.w`, 홀수 주소, 68020 `Bcc.L`(disp 0xff)에서 탐색을 멈추고 `invalid_stops`로 센다. RTS/RTE/RTR/ILLEGAL/JMP/BRA는 fall-through 하지 않는다.
2. 층(layer)은 누적 순서대로 발견된 명령어에 최초 도달 층을 붙인다.
   - A: 카트리지 벡터(0..0x7f 중 고정 ROM을 가리키는 항목: 0x202, 0x20c, 0x29c)와 Neo Geo 헤더 JMP 슬롯 0x122/0x128/0x12e/0x134(`4ef9` 확인). 직접 흐름(BRA/Bcc/DBcc/BSR/JSR/JMP abs·PC-relative)만 따라간다. 슬롯 위치는 Neo Geo 헤더 관례 [I], ROM의 `4ef9` 존재는 [F].
   - B [I]: A·B 코드에서 발견한 즉시 코드 포인터 — `MOVE.L #imm,<(An),(An)+,-(An),d(An),d8(An,Xn),abs,An>`, `LEA`/`PEA`(abs.w/abs.l/d16(PC)) — 와 `JMP/JSR (d8,PC,Xn)` 바로 뒤의 BRA 테이블 항목(연속 BRA, 최대 256개). 포인터 대상은 짝수, 0x100 이상, 첫 4개 명령어(또는 종결 명령어까지)가 유효하고 0x0000/0xffff 채움이 없어야 root가 된다.
   - R [F 입력 / I 결과]: `animation_machine.cpp`의 라우팅 PC 원자 시작점(범위 시작·`==` 값)을 root로 추가하고 그 코드의 포인터·테이블도 같은 층 R로 따라간다. 라우팅 범위가 정의상 R을 키우므로 R의 "커버율"은 순환적 성격이 있다. 독립적인 신호는 A, A+B 수치와 "라우팅 범위 중 미발견 바이트"다.
   - C [I]: 남은 틈의 선형 스윕(유효 명령어 4개 이상이 종결 명령어로 끝나는 구간). A/B/R과 섞지 않고 보고서 `heuristic_sweep`에만 남긴다.
3. 라우팅 범위: `next.pc>=A && next.pc<B`/`<=B`, `&& next.pc!=X`(범위 분할), `next.pc==V`를 정규식으로 추출해 병합(인접 포함). 상수 비교 730개 모두 매칭(`next.pc==stop_pc`는 상수가 아니라 제외). `stage_event_ops_trap(next.pc)` 같은 비PC 술어는 모델링하지 않는다 — 해당 블록은 범위 전체를 라우팅으로 센다 [I].
4. 커버율 = 시작 PC가 병합된 라우팅 범위 안에 있는 발견 명령어 / 전체 발견 명령어. 바이트 기준도 병기한다.
5. 문서 범위 [I]: `docs/analysis/*.md`의 `0xA..0xB`(고정 ROM, 짝수 시작, 0x8000바이트 이하, [A,B) 가정) 27개 범위(병합 12,739바이트, 출처 18개 파일은 보고서 `inputs.documented_range_sources`)를 라우팅 범위에 더한 보조 수치다. 데이터 표나 VRAM 값이 섞일 수 있어 느슨한 신호로만 쓴다.

## 한계
- [F] 간접 점프 미해결: `JMP/JSR (An)` 39, `d(An)` 1, 기타 인덱스 7, 테이블 없는 PC-index 1(총 48). `MOVE.L #imm`으로 RAM 슬롯에 설치되는 콜백이 RAM 경유로 호출되는 경로, 오프셋 워드 표(`MOVE.W tbl(PC,Dn),Dn; JMP`)는 따라가지 않는다.
- [F] 포인터 root 후보 805개가 개연성 검사로 거부됐다(lea 446, move.l 359). 반대로 수락된 포인터가 데이터를 가리킬 수 있다 [I].
- [F] 명령어 겹침(다른 명령어 본문 안에서 시작) 185곳, 유효하지 않은 opcode 정지 135곳, 흐름 대상 불량(홀수 62, <0x100 12, 고정 ROM 밖 103). 코드/데이터 경계와 인라인 데이터(JSR 뒤 인자 등)는 구분하지 못한다.
- [U] 뱅크 코드는 PVC `bank_base` 상태가 필요해 포함하지 않았다. 고정 영역만의 수치다.
- [I] `distinct_roots`·층 귀속은 탐색 순서에 의존하는 설명용 정보이며, 명령어 집합 자체는 순서와 무관하다.
