# 사운드 타이머 원본 실행 근거

원본 복호화 프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
고정 CPU 주소48156과 ROM 오프셋48156은 같다. RAMd68c의 word를 읽고0이면 즉시 반환한다. 나머지는 signed word로15와 비교한다.15 이하이면 RAM word를1 증가시키고, 양수16..32767이면 RAM word와 D0 전체를0으로 만든다. 이후 D0.word에19c0을 더해3af8을 호출한다. 증가한 타이머 값이 아니라 증가 전 값으로 명령을 만든다.

음수 word도 증가 경로를 타며 ffff는 RAM을0으로 만들고 명령19bf를 전달한다. MOVE.W/ADDI.W 경로는 D0 상위16비트를 유지하지만 양수 초과 경로의 MOVEQ는 상위를0으로 만든다. 따라서16프레임 카운터라는 추정만으로 unsigned 범위 밖 동작을 없애면 원본과 달라진다.

`tools/analyze_sound_timer.py`는 모든65,536개 word를 원본48156에 넣고 실제3af8 첫 명령 직전 또는 반환에서 멈춘다. 전체64KiB RAM, D0 전체, 명령 word, 실제 분기 경계와 RAM/JSR 스택 쓰기 순서를 검증한다.0의 반환1건, signed nonzero<=15 증가32,783건, 양수 초과 초기화32,752건을 확인했다. 실제 생산자 진입은65,535건이며 원본 ROM은 변경하지 않았다.

보고서 `artifacts/sound_timer/analysis.json` SHA256: `5fb57e5d7503517ff80f4447dc47993638f1f59048d50bc6637efc540f5e121c`.

이 분석은3af8을 실행하거나 C++ 타이머와 비교한 것이 아니다. 다음은 타이머에서 word 생산/대기와3cb2 소비로 이어지는3cac 연결이다. 자연적인 IRQ 주기나 오디오 시간축은 아직 입증하지 않았다.
