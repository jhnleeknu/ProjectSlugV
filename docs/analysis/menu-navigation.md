# 메뉴 항목 이동

## 원본 근거와 범위

프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
고정 ROM이므로 아래 CPU 주소와 복호화 프로그램 파일 오프셋은 같다.
`0x00a216`은 방향에 따른 이동, `0x00a280`은 지정 인덱스 선택이다.
선택 후 `0x009d3a`를 두 번 호출하고 반환하는 범위를 C++ `navigate_menu`로 구현했다.
입력 판정의 `0x00a566/0x00a574`에서 방향 비트를 설정하는 부분 및 후속 event 0 실행은 이 API 밖이다.

## 확인한 연산과 호출 순서

- 현재 슬롯은 RAM `0x107f12`가 가리킨다. 슬롯+7은 선택 인덱스, +8은 그릴 항목, +6은 항목 수다.
- 슬롯+15 bit1이 0이면 byte 증가 후 count 이상에서 0으로 순환한다. bit1이 1이면 byte 감소 후 borrow가 생길 때 count를 더한다.
- 명시적 선택은 D0의 하위 byte를 사용한다. count 이상이면 count-1로 보정한다. 부적합 항목이면 기존 방향 비트에 따라 계속 검색한다.
- item+4 콜백이 0이거나 item+0 제목 주소가 `0xfffffffe`이면 건너뛴다. 제목 주소 0은 선택 불가능 조건이 아니다.
- 새 선택을 슬롯+7에 기록한 상태에서, 슬롯+8을 이전 인덱스로 두고 이전 행을 그린다. 그 다음 +8을 새 인덱스로 바꾸고 새 행을 그린다. 같은 항목을 다시 선택해도 두 번 그린다.
- 두 번 모두 A1=`0x00a008`의 가림 처리를 사용한다. 보이는 행의 event 5 콜백은 각 그리기 후 호출된다. 마지막으로 슬롯+14에 0을 기록하여 다음 이벤트를 대기시킨다.
- 행 표시 조건은 `uint8(index+1) < visible_height`다. 조건이 거짓이면 원본은 리소스나 콜백을 참조하지 않고 바로 반환한다.

`draw_menu_item`은 기존 전체 메뉴 그리기와 행 출력 구현을 공유한다. MS5D에서 제목/콜백/인자를 읽고 원본과 같은 폭과 순서의 비디오 포트 쓰기를 만든다. PNG는 사용하지 않는다.

## 계약과 아직 지원하지 않는 경로

정상적인 count(1..255), descriptor의 항목 수와 일치하는 슬롯, 유효한 기존 인덱스를 요구한다. 선택 가능한 항목이 없는 원본 검색은 끝나지 않으므로, 한 바퀴 탐색 후 오류를 반환한다. 오류에서는 전체 RAM과 출력 목록을 보존한다.

보이는 행 출력은 flags 0과 기존 여섯 event-5 무효과 콜백(`9488/94d6/949a/94b8/950c/9532`) 또는 콜백 0을 지원한다. 구분선은 검색에서 건너뛰지만 이전 선택이 보이는 구분선인 경우의 그리기는 아직 지원하지 않는다. 다른 콜백/flags 역시 명시적 오류다. 보이지 않는 행은 원본처럼 해당 검사를 하지 않는다.

원본 명령 실행의 중간 RAM 쓰기 시점, CPU 레지스터 전체, 실제 인터럽트와 화면 픽셀 타이밍까지 재현했다고 주장하지 않는다. 여기서는 호출 전후 전체 RAM과 순서 있는 포트 쓰기를 비교한다.

## 재현

```
make all test
.venv/bin/python tools/verify_menu_navigation.py
.venv/bin/python tools/analyze_menu_text.py --cpp
build/navigate_menu INPUT_RAM INPUT_MS5D OUTPUT_RAM OUTPUT_WRITES step 0
build/navigate_menu INPUT_RAM INPUT_MS5D OUTPUT_RAM OUTPUT_WRITES select 5
```

출력 쓰기 목록은 size byte + BE32 CPU 포트 주소 + BE32 값의 9-byte 진단 레코드다. 실제 게임 리소스 형식은 기존 MS5D를 유지한다. 검증 결과는 `artifacts/menu_navigation/verification.json`에 기록한다.

## 검증 결과

원본/C++ 전체 RAM 및 순서 있는 포트 쓰기 1,986조건이 일치했다. 실제 93e0 메뉴 432조건, 비활성/구분선 432조건, 선택 가능 항목 하나 324조건, 여섯 콜백의 인자 648조건, 숨겨진 행의 비영 flags 108조건, count255 경계 24조건과 count1 경계 18조건을 포함한다. 잘못된 요청 12조건은 출력 파일을 만들지 않았다. C++ 단위 검사에서는 실패 전후 RAM과 기존 출력 목록 보존을 확인했다. 기존 전체 메뉴 288조건 회귀 및 `make all test`도 통과했다.

## 두 행의 전체 레지스터 연결

`navigate_menu`는 선택적 D1/D3를 이전 행과 새 행의 `draw_menu_item`에 순서대로 전달한다. a216/a280의 선택 탐색 자체는 이 두 레지스터를 바꾸지 않는다. 숨은 행도 D1 하위 byte를 바꾸므로 포트 출력이 없는 이동을 무조건 레지스터 불변으로 처리하지 않는다. line과 D3를 함께 전달하면 하위 word 일치를 요구한다. 실패 시 모든 출력은 보존한다.

`navigate_menu --registers D1 D3` 진단 모드는 line/D1/D3 JSON을 출력한다. 기존 위치 인자와 기본 무출력 동작은 유지한다.

후속 통합 근거: a6da는 각 슬롯에서 9b58 테두리 후 9e1a 텍스트를 호출한다. 전체 레지스터 연결 시 두 호출의 반환값을 다음 슬롯으로 순서대로 전달해야 한다. 949a/94b8/94d6의 event3은 9f36에서 좌표와 D1을 설정한 뒤 a0a0으로 진입하므로, 상위 이벤트 디스패처의 D1을 단순 보존하면 안 된다. 이 상위 스택/이벤트 연결은 이번 변경 범위 이후 작업이다.
