# 임시 색 효과의 저장과 복구

프로그램 SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 아래 주소는 고정 ROM의 CPU 주소와 파일 오프셋이 같다. RAM 주소는 CPU100000을 기준으로 표기한다.

## 원본 상태와 복구 규칙

8bc8은 RAM7dc2..7dd5의20바이트를7dd6..7de9로 복사한다. 현재색6바이트, 목표색6바이트, 증분6바이트, 타이머1바이트와 준비 임시 플래그1바이트가 포함된다. 전송 counter7dea 및 pending7ded는 포함하지 않는다.

8be0은 복구 전 현재색의 상위 byte 세 개(7dc2/7dc4/7dc6)를 보관한 후20바이트를 되돌린다. 복구한 timer7dd4가 nonzero면 종료한다. timer가0이면1로 바꾸고 세 상위 byte만 복구 전 값으로 다시 쓴다. 하위 byte는 저장된 값을 유지한다. 따라서 단순20바이트 복사만으로 복구를 구현하면 원본과 다르다.

기존5728 갱신과 조합하면 timer1은 다음 갱신에서0이 되며 저장된 목표 word로 현재값을 옮긴다. 상위 byte의 변화를 검사해 영향받는 팔레트를 dirty로 만드는 경로를 지나간다. 실제 화면 변화 및 IRQ 타이밍은 별도 검증 대상이다.

## 실제 호출 근거

고정ROM f94에서8bc8을 호출하고 fa0..fa8은(-4,-4,-4,4)로8c16을 호출한다. fae는5728을 호출한다. fd6의8be0 호출은 object+80 플래그 검사 뒤에 있으며, 복구 후 그 플래그를0으로 만든다. 이 호출 구조는 확인했으나 이를 특정 게임 메뉴나 자연 입력 이벤트라고 단정하지 않는다.

별도로 c52a에서 시작하는 코드에는 c554의채우기설정8b64 호출, object의함수포인터를c560으로 변경하는 명령이 있다. c560은8bb6으로counter7dea를 읽고 nonzero면 반환하며0이면c56e로진행한다. 이는 정적 제어흐름 근거이며 c52a까지의 자연도달성은 미확인이다.

## C++ 구현과 검증

`save_palette_effect`와 `restore_palette_effect`는 정확히65536바이트RAM을 받는다. 크기 오류 시 상태를 바꾸지 않는다. CLI는 `snapshot_palette save|restore INPUT_RAM OUTPUT_RAM`이다.

```
make all test
.venv/bin/python tools/verify_palette_snapshot.py
```

원본68000과 전체RAM을 대조한다. 저장16조건, 복구512조건(타이머0..255 × 서로 다른 상태2종), 복구 후 갱신8조건을 검증했다. 실제 호출의 효과값을 사용한 저장→임시효과설정→4회갱신→복구→갱신의8단계도 일치했다. 후속 갱신은 pending gate를 세워 색 상태와dirty표시만 검사하며, 이 검사를 화면 업로드 검증으로 주장하지 않는다.
