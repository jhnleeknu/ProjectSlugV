# 스테이지 시작 콜백의 명령 근거 목록

## 범위와 원본

canonical 프로그램은 `extracted/program/maincpu.decrypted.be.bin`이며 SHA256은 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`다. 이 문서의 코드·테이블 주소는 첫1MiB의 고정 ROM CPU 주소이며 같은 값의 복호화 파일 오프셋에 대응한다. MMIO 주소와 RAM 주소는 프로그램 파일 오프셋이 아니다. A5 상대 피연산자를 RAM 주소로 표현하는 부분은 A5=`108000` 조건을 명시적으로 사용한다.

근거는 `tools/inventory_game_ready.py`와 `tools/inventory_stage_startup.py`가 생성한 명령 후보 목록이다. 여기서는 CPU 실행을 새로 관측하지 않았다. 자동 디코딩·직접 주소 참조와 동작 의미 해석을 구분하며, 전체 콜백·스테이지 시작·자연스러운 스케줄러 실행의 분석 완료를 주장하지 않는다.

## 477e4의 초기 명령 순서

아래는 `artifacts/game_ready/inventory.asm`의 명령 주소 순서다. 분기가 있는 경우 실제 실행 순서를 한 경로로 고정하지 않는다.

| `477ee`, `477f4` | A5+5680/+5681의 byte를 A6+7c/+7d에 각각 저장한다. |
| `477fa..47800` | D0을0으로 만든 뒤 A6+7c.byte를 읽고 `474e2`를 호출한다. |
| `47804` | `(A0).byte`를 A5+5684에 저장한다. |
| `47808..4780e` | D1을0으로 만든 뒤 A6+7d.byte를 읽고 `47540`을 호출한다. |
| `47812..4781e` | A0을0과 비교한다.0인 분기는 A6+7d.byte를 지우고 `477fa`로 돌아간다. 이 반복의 종료는 여기서 증명하지 않는다. |
| `47820` | A0.long을 A6+76에 저장한다. |
| `47824`, `4782a`, `47830`, `47836`, `4783c` | 각각 `ca48`, `1c5b0`, `ca7e`, `4e24e`, `9056` 직접 호출이다. |

`478ac..478c4`는 여섯 개의 BRA 명령이며 일반 숫자 포인터 표로 재해석하지 않는다. indexed JMP 앞에4배 연산은 없다. 레코드 첫 byte가 어떤 명령 경계를 선택하는지와 유효 값은 별도 검증 대상이다. 기존 bounded 목록은 `479b0` exclusive에서 끝나며 그 뒤 콜백 continuation을 포함하지 않는다.

## 기존 스테이지 리소스와의 주소 연결

`474ee`의 `MOVEA.L $474f4(PC,D0.word),A0`가 고정 포인터 인덱스 `474f4`를 직접 참조한다. `pack_stage_catalog.py`의 INDEX도 `474f4`이고 `stage_index.ms5d`와19개의 `stage_group_00.ms5d..stage_group_18.ms5d`를 보존한다. 원본 `474e2`/`47540` 조회와 기존 `StageCatalog`를 사용하는 일반 함수 `query_stage`의 검증 범위는 [stage-catalog.md](stage-catalog.md)에 기록되어 있다.

`4780e`에서 호출한 `47540`의 반환 A0을 `47820`이 A6+76에 보관하고, `47896` 이후 같은 포인터의 첫 byte를 읽는다. 따라서 기존 MS5D 그룹 리소스의 원본 payload 주소와 이 포인터 참조는 연결 근거가 있다. 이 사실만으로18바이트 header의 전체 의미, 별도 맵 리소스 연결, 실행 가능 스테이지 또는 모든 indexed JMP 값의 유효성을 확정하지 않는다. `477e4`가 읽는 payload 첫 byte와+10.word도 원본 바이트 그대로 남아 있어야 한다.

## 명령에 직접 나타나는 저장

A5=`108000`일 때 다음 표의 A5 상대 offset은 해당 RAM 위치에 대응한다. 중간 callee가 같은 위치를 변경할 수 있으므로 표를 함수의 최종 RAM 상태로 사용하지 않는다.

| 명령 주소 | 저장 명령 사실 |
|---|---|
| `1a5a4`, `1a724` | A5−7ff0.word에 각각1/0을 저장한다(RAM100010). |
| `1a5ba` | A5+541c.word에 D0.word를 저장한다. |
| `1a5c2`, `1a5c8`, `1a5ce` | A5+5418/+5426/+5428.word에 각각0/a0/80을 저장한다. |
| `1a5d4`, `1a5d8`, `1a5e8`, `1a5ec`, `1a5fc` | A5+542a/+542c/+5448/+544a/+544c.word를 지운다. |
| `1a5dc`, `1a5e2` | A5+5444/+5446.word에8000을 저장한다. |
| `1a5f0`, `1a5f6` | A5+5442/+5440.word에7fff를 저장한다. |
| `1a600`, `1a606` | A5+542e/+5430.word에ffff를 저장한다. |
| `1a60c..1a61c` | A5+5432.word, +5434/+5438.long, +543c/+540c.word를 지운다. |
| `1a620` | 절대 RAM10d44e.byte를 지운다. |
| `1a674`, `1a68a` | A5+541c/+5418.word에 D7.word를 저장하는 명령이 있다. |
| `1a696`, `1a69a` | A5+53bc/+53c0.long에 D0/D1을 저장한다. |

PVC 절대 word 저장은 네 개다. `1a5aa`의 `33fc2000002ffff2`는 주소2ffff2에2000, `1a5b2`의 `33fc0000002ffff0`는2ffff0에0을 쓴다. `1a72a`의 `33fc1000002ffff2`는2ffff2에1000, `1a732`의 `33fc0000002ffff0`는2ffff0에0을 쓴다. 하위 callee의 추가 MMIO, ROM bank 매핑, 표시 결과는 이 네 명령만으로 추정하지 않는다.

별도 짧은 진입의 직접 명령은 다음과 같다. `ca48`은 A5−7699.byte에ff를 저장한다(A5 조건하 RAM100967). `4e24e`는 A5+5d1f.byte를 지운다(RAM10dd1f). `9056`은 절대 RAM107def.byte에ff를 저장한다. `1c5b0`은 A0=`100cb8`/`100da8`을 각각 설정해 `289e`를 호출하고 BCC로 분기하며, 각 경로에 A0+61.byte bit6 및 A0+a8.byte bit0의 BSET 명령이 있다. 호출의 carry 계약과 최종 효과는 별도 의미 검토 사항이다.

## 메인의 추가 원시 바이트 확인

다음 근거는 초기 bounded 목록 이후 메인이 원본을 직접 확인해 전달한 내용이다. 현재 목록 도구가 이 긴 구간과 모든 분기를 자동 재현하는 것은 아니므로 별도 재생성 검사를 다음 작업으로 남긴다.

`17292`는 A1=A0+80, D0 전체=0을 설정한다. canonical 프로그램의 `[17298,18298)`는 정확히 `22c0` 명령2048개의 연속 바이트와 일치하며 `18298`은 `4e75` RTS다. 각각 long 저장이므로 총8192바이트다. 호출부 A0=`109156`에 대응하는 저장 범위는 `[1091d6,10b1d6)`, A0=`10b1d6`에 대응하는 범위는 `[10b256,10d256)`다. 이 명령 반복과 범위는 원시 근거이며 다른 callee의 부작용을 포함하는 최종 상태 계약은 아니다.

`1a7a8`의 메인 확인 끝은 `1a90e`의 RTS이며, 내부에서 `43ea8`, `1724c`, `1726c`, `1728c`, `1afda`, `19e64`를 호출한다. 기존 `update_position`은 `43e38`/`43ea8`의 RAM 효과만 지원하므로 그 API를 재사용해도 이 호출자의 레지스터 계약이 충족되는지는 별도 확인이 필요하다. 분기·반복·다른 callee의 효과는 아직 이 문서에서 해석하지 않는다.

`1afda`는 RAM10f000의 bit3/4에 따라 분기한다. 따라서 초기 D0=0/A0=0이라는 사실만으로 `1a5a4` 전체를 단순 zero 작업으로 축약할 수 없다. 메인이 확인한 `1b07c..1b0de` 경로에는 초기 D2=27/D3=1f와 DBRA 반복으로40열×32행의 VRAM3c0000 long 쓰기가 있다. 그 하위 `1b0e0`은 고정 표 `1af12`/`1afd2`를 참조한다. 임의 debug flag까지 동등하게 지원하려면 이 표의 원본 MS5D 리소스 계약이 필요할 가능성이 있으나 아직 미정이다. 이 경로는 미복원이며 기본 flag0만을 전체 완료 기준으로 축소하지 않는다.

## 재사용 후보와 남은 검토

주소 검색에서는 위16개의 `1a5a4` callee에 대한 기존 엔진 구현 근거를 찾지 못했다. `column_control`, `sprite_pool`/`sprite_queue`/`sprite_producer`/prepare·refresh queue, `video_control`, `position_state`, palette 관련 API는 구현 가족을 탐색하기 위한 후보일 뿐 동일 주소·동일 효과의 증거가 아니다. 특히 `43e22`를 기존 `update_position`과 동일하다고 치환하지 않는다.

`9056`의107def.byte 저장은 기존 `main_startup.cpp`와 `game_startup.cpp`에 주소/값 참조가 있다. `289e` 판정은 [game-continuation.md](game-continuation.md)의 메인 분석과 연결되지만, 이 목록 자체는 독립 실행 검증을 추가하지 않는다. 전체 `1c5b0`와 초기 `477e4`를 기존 API 조합으로 대체할 수 있는지는 메인의 효과·레지스터·오류 경로 리뷰 이후 판단한다.

현재 조사 도구는 `disassemble_range`의 실길이 검사를 사용한다. `1a5a4`를128바이트로 자르면 `1a620`의 절대 CLR.B가 잘리므로 이 진입만 최대512바이트로 확대했다. 그 결과 첫 RTS는 `1a73a`, 끝 exclusive는 `1a73c`다. 다른 진입 끝은 ca50/1c5ea/4e254/9060이다. helper 후보는 최대128바이트와 첫 선형 RTS/undecoded word 경계로 제한된다. 따라서 더 짧은 첫 RTS 뒤의 별도 분기 경로, 잘린 명령 이후, 코드·데이터 불명확 구간을 완료된 함수 분석으로 취급하지 않는다. 도구 개선을 추가 실행하기보다 이 제한을 보존한 뒤 다음 단계에서 각 callee의 실제 CFG와 부작용을 확인해야 한다.

재생성 명령은 `.venv/bin/python tools/inventory_stage_startup.py`다. 작성 시점의 `artifacts/stage_startup/inventory.asm` SHA256은 `adf864ea601193ad7d543bc0124e1dcd7af021edcf87f28b7e275fe2c26a1407`이고 report는 `6664908c593cd78cb6b8b8763b6df4e4541d093b84eae917e81a08c769330928`이다. report의 텍스트 주소 참조는 문서 추가로 재생성 시 달라질 수 있다. 이번 문서 작업은 도구·C++·STATUS·리뷰 기록·ROM을 수정하지 않는다.
