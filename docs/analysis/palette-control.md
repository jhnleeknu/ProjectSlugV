# 팔레트 효과·혼합 설정 함수

대상SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 고정ROM 주소는 CPU/파일 동일하다.

## 효과 설정8c16

D0.W/D1.W/D2.W를 signed16으로 해석해 각각[-31,31]로 제한하고256배한word를 RAM107dc8/a/c 목표에 기록한다. D3의하위byte가0이면기간1, 그 외에는그대로107dd4에 쓴다. 각 목표에서현재107dc2/4/6을 뺀 **하위16비트**를 signed확장하여 기간으로 DIVS한다. 몫은0쪽절단이고7dce/7dd0/7dd2 step word에 기록한다.

세차이가 모두0이면timer를0으로만들고 기존step word를 보존한다. 현재값이나dirty표시는 이설정함수에서 바꾸지 않는다. 이후5728 갱신에서step을누적하고 마지막호출에목표를직접대입한다.

실제ROM `fa0..fb4`는D0/D1/D2=-4,D3=4를설정하고fa8에서8c16,fae에서5728을연달아호출한다. 도구가이20바이트를정확히검증한다. 이근거는두함수의실제직접연결이며 해당상위게임상태의자연도달성이나전체프레임동기화까지증명하지않는다.

## 슬롯 혼합 설정8cda

D0의하위byte로선택한16바이트node의참조word+8이0이면무동작이다. 그외에는D2의하위byte계수를unsigned로32까지제한한다. D1.W가node+c target과다르면target과계수byte+e를갱신하고dirty bit7을설정한다. target이같고계수만다르면계수를갱신하되target이원본ID+a와다를때만dirty를추가한다. ID목록이나참조횟수는바꾸지않는다. 계수32는준비함수에서두번째팔레트끝점으로처리된다.

예시직접호출1d0f6..1d104는object+1a의slot에target0,계수8을전달한다. 일반JSR 패턴검색은8c16후보31개,8cda후보14개를기록했으며 후보목록전체를실행도달성으로간주하지않는다.

## 검증

```
make all test
.venv/bin/python tools/verify_palette_control.py
```

효과설정505조건(부호/제한/word차이wrap/기간/일치시step보존),혼합432조건(참조0/1/ffff,slot0/255,target같음/다름,계수경계)의원본과C++ 전체RAM이일치했다. 총937조건. 전체기존검사도통과했다. 레지스터/CCR·스택변화는RAM API계약밖이다.

전역효과설정·진행·팔레트준비계산은연결할수있지만, 모든게임상태의호출과장치업로드동기화, 오브젝트별계수변화의상위로직은아직전체복원되지않았다.
