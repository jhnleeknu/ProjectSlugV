# `480bc` 프레임 helper 묶음 U5: script opcode·배치 `1a0b6`/`1a470` 계약

**상태: 메인 리뷰를 거쳐 확정(아래 메인 결정). 구현·검증 기록이 아니다.** 범위 근거는 `animation-machine-480bc-scope.md`의 U5, 진입 경계는 확정된 U2 계약(`animation-machine-scene-core-u2-contract.md`)의 `1a292` BSR 대상 `1a0b6`과 `1a466` BSR 대상 `1a470`, 그리고 U4 계약(`animation-machine-scene-update-u4-contract.md`) 메인 결정 3이 U5로 넘긴 `43e08`/`43e22` stub이다. Claude Opus 5.5 / high 분석 작업자가 canonical BE ROM(SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`, `extracted/program/maincpu.decrypted.be.bin`, 8 MiB, fixed CPU 주소=file offset, banked window `200000+`는 bank `1000`→physical `200000`, `2000`→physical `300000`)을 capstone M68000으로 디코드하고 기존 관측 산출물을 읽기 전용으로 재생해 작성했다. U1~U4 실행부는 작업 트리 `/Users/start/Workspce/metalslug-input`(HEAD `b6b79ac`, WIP)의 `engine/src`를 읽기 전용으로 참조했다. [F]=원본 바이트 또는 기록된 산출물에서 확인한 사실, [I]=추론, [U]=미확인. 명령 단위 정답은 원본 바이트 자체다. 같은 루틴들의 typed host 재구성(`engine/src/scene_command.cpp`·`scene_placement_execution.cpp`·`scene_node.cpp`·`stage_cue_control.cpp`, 문서 `scene-command.md`·`scene-command-dependencies.md`·`scene-placement-execution.md`·`scene-node.md`)은 machine 실행부가 아니며 교차 확인 자료로만 쓴다.

메인 결정(Claude Opus 5.5, 원본 대조 리뷰 후, 초안 권고를 모두 채택): (1) `3d7e`의 `3c0006` WORD 쓰기는 U5 실행부 지역 port helper로 VideoPortWrite(address `3c0006`, size 2)로 기록한다(공용 am_write는 바꾸지 않음). native 관측의 video 영역도 `3c0006`을 포함하도록 확장한다. (2) `43e08`/`43e22`는 기존 cleanup 실행부(`animation_machine_cleanup.cpp`)의 새 case 2개로 추가한다(routing 분할 없음). (3) 범위 밖 script opcode와 `1a086`/`1a09e` 표 index는 U2~U4와 같은 계산 PC·live 읽기 정책을 따른다. (4) `1a470`의 `28ae` 실패 경로(carry 무시, fallback A0=`100e98` 쓰기)는 원본대로 구현한다. (5) `1a514` 복사 loop는 원본대로(홀수 길이 무한 loop는 기존 block budget 오류, 8000 이상 길이의 부호 차이 유지). (6) 자연 seed가 실행하지 않는 5 block도 모두 구현하고 합성 host write로 검증한다. (7) opcode 04는 card_child `de42e` 선례처럼 bank 초기화 뒤 `20000c` live 읽기이며 bank 1000·`100010`=0이 frame 끝까지 유지된다.

## 메인 결정 필요 항목

1. **Port `3c0006` WORD 쓰기(`3d7e`, script opcode 40)**: [F] 기존 machine 공용 `am_write`(`engine/src/animation_machine.cpp` 222행)는 RAM `100000..1fffff`와 PVC `2fe000..2fffff`만 받고 그 밖은 `unsupported animation machine write device`로 실패한다. `3c0000`/`3c0004`/`300001`은 각 실행부가 지역 helper로 `VideoPortWrite`를 직접 push한다(`animation_machine_screen.cpp`·`hud.cpp`·`scene.cpp`·`transition.cpp`의 `port_or_memory`). `3c0006`을 쓰는 machine 실행부는 아직 없다. typed `scene_command.cpp`(opcode 40)는 `VideoPortWrite{size 2, 3c0006, WORD 104d90}` 1개를 이미 쓴다. [F] machine 원본 관측기들(`tools/observe_animation_machine_*.py`)의 video region 허용은 `3c0000`(2/4)·`3c0004`(2)뿐이다.
   - 선택 A(**작업자 권고**): U5 실행부 지역 helper로 원본 쓰기 1회=`VideoPortWrite{address 3c0006, size 2, value}` 1개(기존 `3c0000` 규약과 같음), device 상태 없음. U5 검증용 관측기에서 WORD `3c0006`을 video region으로 허용한다.
   - 선택 B: 공용 `am_write`에 `3c0006` WORD를 추가(모든 실행부에 영향, 기존 회귀 재실행 필요).
   - 선택 G: `3d7e`를 경계로 두고 stop만 허용. 그 경우 scene_frame seed `588..591`(opcode 40 실행)은 U2~U5 결합 전체 프레임 비교에서 빠진다.
2. **`43e08`/`43e22` stub의 소속**: [F] 두 PC는 기존 cleanup 라우팅 범위(`animation_machine.cpp`의 `43dcc..43ea2`, `<=`) 안에 있고 현재 `animation_cleanup_block` default(`unsupported animation machine PC`)로 거부된다. 두 stub은 각각 한 block이며 끝이 `BRA 43e38`(cleanup 실행부의 기존 `cleanup_coordinate`)이다.
   - 선택 A(**작업자 권고**): `engine/src/animation_machine_cleanup.cpp`의 `animation_cleanup_block`에 `case 0x43e08`/`case 0x43e22` 두 개를 추가하고 `r.pc=0x43e38`로 넘긴다. 근거: 라우팅 표를 바꾸지 않는다(같은 범위가 이미 cleanup으로 간다), BRA 대상이 같은 실행부 안에 있다, 범위 안 다른 미지원 PC(`43e04`·`43e34`, 둘 다 `LEA 2e(A6),A0` 진입)는 그대로 default 거부로 남는다. 비용: 기존 cleanup 회귀를 다시 돌려야 한다.
   - 선택 B: 라우팅 분리(`43dcc..43e08`, `43e34..43ea2`→cleanup, `43e08..43e34`→U5 실행부). 공용 라우팅 식이 늘고 `43e04`/`43e34`의 소속을 따로 정해야 한다.
3. **Script opcode index 정책(`1a0b8`)**: [F] `JMP 1a0bc+sext(D7.W)`이며 범위 검사가 없다. U2(`1a284` TST.W+BPL)를 거친 진입이면 D7.W는 `0..7fff`(같은 WORD를 두 번 읽고 그 사이 쓰기 없음). U2~U4 메인 결정과 같이 계산된 PC로 그대로 이동하는 안(지원 block 시작이면 실행, 아니면 기존 `unsupported animation machine PC`, 홀수면 기존 홀수 PC 오류, 전용 오류 없음)을 제안한다. 예: `50`→`1a10c`(opcode 10 본문, 실행), `52`→`1a10e`(block 중간, 거부), `5a`→`1a116`(0c 본문, 실행), `60`→`1a11c`(30 본문, 실행), `1ae`→`1a26a`(U2 block 시작, 실행), 홀수→홀수 PC 오류. 같은 정책을 표 읽기 `1a086`/`1a09e`(`MOVEA.L (6,PC,D7.W)`, 아래 의미 7)에도 적용하자고 제안한다: 원본처럼 `1a08e+sext(D7.W)`/`1a0a6+sext(D7.W)` LONG을 live bus로 읽고(fixed ROM `1208e..2208d` 범위, 홀수면 기존 홀수 접근 오류), 결과 포인터의 후속 접근 오류는 기존 checked 오류로 처리한다.
4. **`28ae` 실패 무시와 fallback A0=`100e98`(범위 문서 미확인 9)**: [F] `1a4e8` JSR `28ae`의 반환 C를 아무도 소비하지 않고, 실패 시 `28ae`가 남긴 A0=A5−`7168`(=`100e98`)로 `43e08`(`100ec6..`)과 payload 복사(`100f0e..`)를 그대로 실행한다. 원본 그대로 구현(전용 guard 없음)을 권고한다. [F] scene_frame `576`/`577`(`104ca0`=0)이 이 경로를 실제로 탄다. [U] `28ae`는 부모 A6(`0c(a0)`·`10(a6)`·`8(a6)`·`6a(a6)` 접근)를 쓰는데 `480bc` 자연 프레임에서 `1a470` 진입 시 A6가 무엇인지 확인하지 못했다(관측 seed는 선언 A6=`100820`).
5. **복사 루프 `1a514`의 길이 정책**: [F] `D0.W=WORD 2(record)`, `TST.W`가 0이면 생략, 아니면 `MOVE.W (A0)+,(A1)+; SUBQ.W #2,D0; BNE`. 홀수 길이면 D0.W가 0이 되지 않아 끝나지 않고(주소 증가로 결국 접근 오류 또는 step 상한), `8000` 이상 짝수는 무부호 길이로 복사되지만 skip 경로(`1a51c`)는 `sext(D0.W)`로 건너뛰어 두 경로의 전진량이 다르다. 원본 그대로 구현하고 상한은 기존 machine step 상한(1,000,000 block, `animation machine block budget exceeded`)에 맡기는 안을 권고한다(U2~U4 루프와 같음). [F] 관측 길이는 0과 2뿐이다.
6. **미관측 경로 포함 여부**: [F] 88 block 시작 중 어떤 관측 출처에서도 실행되지 않은 것은 5개(`1a108`/`1a16e` opcode 4c, `1a24e` opcode 2c 음수 wait, `1a4a2` bbox 비null, `3d84` opcode 40 D0.W=0)다. 전부 구현(합성 host write로 검증)을 권고한다. 근거: 모두 직선 코드 1~3 명령이고 typed 구현이 4c·40(0)을 합성 비교했다(`scene-command.md`).
7. **Opcode 04의 bank 부작용 확인(범위 문서 미확인 11)**: [F] `1a192`는 `am_zero_bank`와 정확히 같은 세 쓰기(WORD 0→A5−`7ff0`, `1000`→`2ffff2`, `0`→`2ffff0`)를 한 뒤 `20000c`를 bank `1000` 상태로 읽는다. 프레임 나머지(`1a790`의 끝 쓰기 전까지) `100010`=0·bank `1000`이 유지된다. 기존 card_child `de42e`/`de444`(같은 바이트 패턴)를 선례로 `am_zero_bank`+live bus 읽기로 구현하는 안을 확인해 달라.
