# 사운드 명령 큐 소비

원본 프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
명령 주소는 고정 ROM CPU 주소와 복호화 프로그램 오프셋이 같다. RAM 오프셋은100000 기준이다.

`service_sound_queue`는3cb2..3d38을 구현한다.3cac의 선행48156 명령 생산 호출은 포함하지 않는다. 호스트가 공급하는320000의byte 읽기 값을4d7c에 저장하고 다음 순서를 따른다.

1. 4d7b.bit7을 지운다. 이전 값이1이면4d7a=ff로 설정하고320000에byte3을 쓴 뒤 반환한다.
2. 읽은 status가1이면 반환한다. 이 경로는f003.bit7을 지우지 않는다.
3. f003.bit7을 지운다. 이전 값이1이면4d7a=ff로 설정하고320000에byte7f를 쓴 뒤 반환한다.
4. 큐 head4d74.word와tail4d76.word가 같으면 반환한다. 같지 않으면4cf4+head의byte를 읽고 head를 `(head+1)&127`로 진행한다. 다음 값이 같고tail에 도달하지 않았으면 같은 방식으로 계속 진행한다. 최종head를 저장하고 첫 명령byte를320000에 한 번 쓴다.

동일 명령의 연속 구간만 합친다. 서로 떨어져 있는 같은 명령을 검색해서 삭제하지 않는다. 명령 값0도 정상byte로 전송한다. 큐 payload는4cf4..4d74의128바이트이고 인덱스는BE16이다.

API의 비어 있지 않은 큐는head/tail0..127을 요구한다. 잘못된 인덱스가 원본에서 항상 즉시 오류가 된다는 뜻은 아니다. 원본은 첫head를 signed word로 주소에 더하며, 범위 밖tail은 순환 탐색에서 도달하지 못할 수도 있다. 이 상태는 지원 범위 밖으로 명시하고, 앞선status·flag 변화까지 취소한다. 우선 명령·status1·head==tail 경로는 큐를 읽지 않으므로 사용하지 않는 인덱스를 검증하지 않는다.

RAM과포트 출력은 실패 시 보존된다. 성공 시 상태 읽기를 소비하고0회 또는1회의byte 쓰기를 반환한다. 사용되는 `VideoPortWrite` 구조체는 기존 공용 MMIO 기록 형태이며 주소320000은 사운드 장치다. 이것은 PCM/WAV 생성이나 사운드 CPU 실행이 아니다.

빌드: `make build/service_sound_queue`.
CLI: `build/service_sound_queue INPUT_RAM OUTPUT_RAM OUTPUT_PORTS STATUS`.
검증: `.venv/bin/python tools/verify_sound_queue.py`.

## 선행 생산 함수의 후속 의존성

3cac은 먼저48156을 호출한다.48156은RAMd68c.word를 읽고0이면 반환한다.0이 아닌 값은 signed 비교로15 이하이면 해당 RAMword를 증가시키고,15보다 크면 RAMword와D0을0으로 만든다. 이어D0.word에19c0을 더해3af8을 호출한다. 음수word도 signed 비교의15 이하 분기에 들어가므로 단순한 양수0..15 타이머라고 가정하면 안 된다.

3af8은 명령 필터·상태 검사와4d82의4word 큐를 사용하며, 큐가 차면3ac8을 통해byte 큐로 밀어낸다.3ac8은byte 큐가 가득 차면3aea에서 소비 위치가 움직일 때까지 기다린다. 따라서 전체3cac와c8c를 연결할 때에는 이 생산·대기·소비 관계를 함께 모델링해야 한다. 이 문단은 명령 근거이며 전체 생산 함수의 동작 검증은 아직 아니다.

## 검증 결과

원본3cb2 실행2,575조건(독립2,565+승계10)에서 전체64KiB RAM과320000의byte 쓰기2,394건이 일치했다. 모든status/command byte, 우선 플래그 조합, 동일 명령 길이1..127과 링 경계, 사용하지 않는 잘못된 인덱스를 포함한다. 실제 status 읽기는 모든 호출에서 정확히1회였다.

우선 명령3→status1 대기→우선 명령7f→일반 큐 소비를 이어받는 시퀀스도 검증했다. 사용되는 잘못된 인덱스와 잘못된RAM14조건은 출력을 보존했다. 원본ROM은 변경하지 않았으며48156을 실행한 것으로 주장하지 않는다.
