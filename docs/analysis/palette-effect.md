# 팔레트 색 효과479e와 혼합 효과504c

프로그램 SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 고정ROM CPU/파일 주소479e는 단일팔레트 효과,504c는 혼합 후 효과다.

479e는 원본word의 세5비트 성분을 분리한다. source bits10..14에는 RAM107dc2,5..9에는107dc4,0..4에는107dc6 byte를 더한다. ADD.B 후 SPL/AND와 CMP/SCC/OR/AND를 적용한다. 정확한 식은 다음과 같다.

```
t = (channel + effect_byte) & 255
result = (t & 128) ? 0 : min(t, 31)
```

8비트 래핑이 먼저 일어나므로 signed effect를 넓은 정수로 더하고0..31로 제한하는 식과 항상 같지는 않다. 예를 들어31+127은 byte158의 부호비트가 켜져0이 된다. 음수처럼 보이는255는31에 더할 때30으로 래핑된다.

504c는 일반혼합4c40과 같은 계수0/31이상 끝점 분기 및 중간 조회표 계산을 수행한 뒤 이 효과를 적용한다. 재조립한15비트 색은 검증된 원본 하드웨어 bit배치로 변환한다. 원본의 A2/A4 보존과 첫색word 미변경도 직접helper 검증에 포함했다.

C++ `prepare_palettes`는 기존 MS5P source_words를 읽어 일반혼합→효과→하드웨어 변환 순서로 처리한다. node flags bit1이 있으면 효과를 우회한다. 효과가 없고 혼합 끝점이면 기존 hardware_words를 사용한다. 효과 끝점의 source bit15는 원본처럼 마스크되지만, 중간 혼합에서 source bit15가 있는 경우는 기존의 미검증 입력 오류를 유지한다.

검증 명령과 결과:

- `tools/analyze_palette_effect.py`:32성분×256효과=8192조건의 원본479e와 모델 일치. 별도32개 팔레트쌍×33계수=1056조건의504c 일치. 총9248조건의 전체RAM 및 A2/A4 보존을 확인했다.
- `tools/verify_palette_blend.py --effects`:실제ID5개×5개×계수33개=825조건. 같은ID, 양쪽 끝점과 중간혼합, 서로 다른 성분 효과와 경계byte를 포함해 원본7196과 C++ 전체RAM 일치.
- `tools/verify_palette_blend.py`:효과없는 기존660조건 회귀.
- `make all test`:전체검사 통과.31+127 경계, 효과우회와 오류rollback 검사 포함.

현재 지원은 준비 함수의 계산이며 게임 프레임의 효과word 갱신과 오브젝트 혼합계수 갱신을 복원한 것은 아니다. 전체 원본 플레이 화면·타이밍 검증은 남아 있다.
