# 큐 단위 스프라이트 갱신

원본 프로그램 SHA256:29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f. 대상 고정 ROM 주소와 파일 오프셋은0x16cfa..0x16ea2다.

## 데이터와 갱신 순서

ready byte0x108d3d bit7이 없으면 상태·비디오 명령을 변경하지 않고 반환한다. 준비된 큐에서는 이 bit를 지우고 방향 byte0x108d3c bit7을 반전한다. 기존 bit가1이면 앞방향,0이면 역방향이다. 다른 bit는 보존한다.

일반 링0x108b34에서 읽기 인덱스0x108d34와 준비 끝0x108d36 사이의 레코드를 소비한다. 앞방향은 읽기부터, 역방향은 준비 끝 직전부터 순회하며512바이트에서 wrap한다. 각 BE word는0x107f34부터의12바이트 레코드 오프셋이다.

슬롯 영역은0x108d3e와0x108d46의8바이트 상태다: 하한, 상한, 앞방향 현재 끝, 역방향 현재 시작의 BE word4개다. 앞방향은 현재 끝을 하한으로 초기화하고 역방향은 현재 시작을 상한으로 초기화한다. 반대 방향의 현재 값은 이미 준비된 슬롯의 경계로 사용된다.

레코드 style bit2로 영역을 선택한 뒤 bit를 지운다. 현재 지원 경로는 레코드+4=0xffff, 지운 style의 하위 byte=0인 일반 단일 직사각형이다. packed ID는 레코드+8 long의 하위23bit, V는 상위9bit다. U는 레코드+2 word를6bit 오른쪽으로 이동한다. 원본 생성기와 같이 이 word의 하위6bit가0인 입력만 허용한다. emitter 내부에서 다시6bit 이동하므로 큐에서 소실된 상위 좌표bit를 재구성할 필요가 없다.

각 레코드의 MS5C 데이터를 찾아 해당 방향의 refresh emitter를 호출하고 다음 슬롯을 갱신한다. 이후 두 영역의 남은 Y 제어를0x8000으로 지운다. 앞방향은 max(현재 끝, 캐시 끝)부터 상한 직전까지0x8201+slot에 쓴다. 역방향은 min(현재 시작, 캐시 시작)부터 하한보다 큰 값까지0x8200+slot에 내림차순으로 쓴다. 마지막에 RAM0x100010 bank shadow를0으로 하고 읽기 인덱스를 준비 끝으로 옮긴다.

## C++ 계약과 검증

refresh_sprite_queue는64KiB RAM과 로드된 CompositionResource 목록을 받고 RAM·순서 있는 비디오 쓰기·처리 여부를 반환한다. 파일·ROM·PNG를 API 내부에서 읽지 않는다. 준비되지 않은 호출은 리소스나 큐 내부 필드를 요구하지 않는다. 지원하지 않는 분기나 잘못된 슬롯·링·리소스는 오류이며 호출자의 RAM·쓰기·처리 여부를 모두 보존한다.

analyze_sprite_refresh_queue.py는 먼저 Python 제어 모델과 검증된 C++ MS5C emitter를 원본0x16cfa 실행에 비교한다. `--cpp`는 완전한 C++ dispatcher와 로더 경로까지 같은 초기 상태로 비교한다. 방향2×ready2×레코드수4(0/1/4/20)×링시작2×캐시3=96조건에서64KiB RAM과 모든 비디오 쓰기를 비교한다. 레코드는 두 실제 리소스와 두 슬롯 영역을 번갈아 사용한다.

## 남은 범위

원본은 bank register0x2ffff2/0x2ffff0도 쓴다. 현재 C++ 런타임은 로드된 리소스를 사용하므로 bank device write를 출력하지 않으며 최종 RAM shadow만 보존한다. 비교의 비디오 이벤트 범위는0x3c0000 포트다. CPU 레지스터·CCR·대기·IRQ 타이밍은 이 API의 계약 밖이다. 두 리소스가 같은 bank에 있는 통제된 실험이며 이 검증만으로 실제 은행 장치 충실도를 주장하지 않는다.

일반 첫 번째 분기만 지원한다. flip·다중블록, 준비 루틴0x16bba와0x166bc의 사전 정렬, producer/consumer 동시 진행, 실제 게임의 프레임 호출·pixel rasterizer는 미완료다.
