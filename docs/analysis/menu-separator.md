# 구분선과 스테이지 메뉴 전체 그리기

원본 프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
다음 CPU 주소는 고정 ROM 파일 오프셋과 같다.

## 9d3a/9cd4의 구분선

항목 title pointer가 `fffffffe`이면 일반 선택 화살표와 문자열 대신 구분선을 그린다. 시작 위치는 메뉴 원점에서 한 타일 오른쪽, 항목 행 위치다. 끝난 후에는 일반 항목과 같이 event5 콜백을 실행한다. native958a의 구분선 콜백은0이다.

원본9d86은 슬롯 폭에서 word로2를 빼고, borrow이면 출력하지 않는다. 9cd4는 첫 타일을 출력한 뒤 남은 수의 하위byte를 감소시킨다. 이 때문에 폭별 출력 수는 다음과 같다.

| 슬롯 폭 | 가려지지 않은 출력 수 |
| --- | --- |
| 0,1 | 0 |
| 2 | 256 |
| 3 | 1 |
| 4..255 | 폭-2 |

첫 타일은0bf8, 중간은0bf9, 마지막은0bfa다. 한 칸만 있는 경우 첫 타일만 쓴다. 각 칸은3c0000에 long 쓰기 한 번이며, 다음 VRAM word 주소로32씩 이동한다. style/선택 여부로 구분선 타일을 바꾸지 않는다.

각 칸은a018의 가림 판정을 받는다. 이 판정은 일반 문자열의clip 선택과 무관하다. 가려진 칸은 쓰기뿐 아니라 주소 이동도 생략한다. 따라서 첫 칸이 가려지면 나머지도 같은 위치에서 검사되고, 두 번째 칸이 가려지면 첫 칸만 출력된다. D3 줄 위치는 구분선 자체에서 변경하지 않는다.

## 엔진 연결

기존 `append_item`에 원본 구분선 분기를 추가하고 `draw_menu_item`/`draw_menu_text`의 구분선 거부를 제거했다. 앞서 연결한9602/9802 콜백과 함께958a/978a의 전체 메뉴를 그릴 수 있다. 리소스 포맷 변경이나 PNG 생성은 필요하지 않으며 기존MS5D 메뉴, 글꼴, 스테이지 카탈로그를 읽는다.

`draw_menu_text` CLI에 다음 선택 인자를 추가했다.

```
build/draw_menu_text INPUT_RAM MENU_MS5D OUTPUT_RAM OUTPUT_PORTS CLIP LINE FONT_MS5D STAGES_DIRECTORY CALLBACK_STACK
```

CALLBACK_STACK은 전체 메뉴 함수 진입주소가 아니라 각 event5 콜백 진입의 원본 A7이다. 새 인자형식만 JSON `line`을 반환하고 기존 인자형식의 조용한 출력을 유지한다. 모든 stage 입력 파일과 출력 사이의 경로/inode 별칭을 검사한다.

## 검증 방법

`verify_stage_menu_draw.py`는 원본9e1a에서958a/978a의 전체 그리기를 실행한다. 코드나 콜백은 변경하지 않는다. 9602/9802 진입에서 A7을 관찰하여 한 번의 전체 그리기 안에서 같은 값인지 확인하고 C++ context에 전달한다. 비교 대상은 전체64KiB RAM, 모든 비디오 포트 쓰기의 순서·폭·주소·값, 최종D3 하위word다.

표시높이는 반드시 slot+4에 설정하며 목표높이+12와 구분한다. 높이0/2/5/12, 선택행, 폭0/1/2/3/4/24/255, 가림 활성/비활성, 부모/현재 메뉴, 좌표·줄·stack 경계 및 범위밖 구역을 비교한다. 폭2의256개 구분선 출력은 원본9cd4 진입 이후 포트 추적으로 별도로 관찰한다.

기존 `verify_menu_navigation.py`도 이전 선택이 구분선인 경우를 포함하도록 확장했다. 폭과 첫/두 번째 칸 가림 조건을 추가하여 구분선에서 다른 선택행으로 이동할 때의 전체RAM/출력을 비교한다. C++ 단위검사는 폭별 출력 수, 타일,clip=false에서도 적용되는 가림과 줄 위치 보존을 확인한다.

```
make all test
.venv/bin/python tools/verify_stage_menu_draw.py
.venv/bin/python tools/verify_menu_navigation.py
```

전체 그리기5,040조건 및 이동2,526조건/오류12검사가 통과했다. 모든 관찰된 event5의진입A7은 전체그리기 진입A7보다20바이트 낮았다. 결과는 STATUS 및 각 artifacts 검증보고서에 기록한다. 이 비교는 렌더링 명령과 RAM 상태에 관한 것이며, 최종 픽셀 화면·하드웨어 타이밍·원본CPU 전체 상태 동등성을 의미하지 않는다.

## 다음 연결

부모 메뉴를 비활성 상태로 다시 그리는 `push_menu`에 stage context와 호출 깊이를 전달해야 한다. 헤더9430과 전체a370의 열기/입력/닫기 순환, 실제 스테이지 실행도 남아 있다. 구분선이 그려진다고 전체 메뉴 실행기가 완성된 것은 아니다.
