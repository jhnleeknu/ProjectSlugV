# 표시 큐 초기화와 기본 생성기

프로그램 SHA256:29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f. 초기화는0xccd6, 생성기는0xcd58이다. 고정 ROM이므로 CPU 주소와 파일 오프셋이 같다.

초기화는 기본 콜백 주소0xcd50(RTS)을 RAM0x109152에 저장하고 큐 인덱스4개·지연 길이·태그·ready byte를0으로 한다. 방향 byte0x108d3c와 레코드 내용은 보존한다. 링256word를0,12,..3060으로 채우고 두 슬롯 영역16바이트는0xff로 채운다. 이0xffff 슬롯 상태는 비활성 영역이다. 준비/갱신은 이를 유지하며 명령을 쓰지 않는다. 표시할 영역은0xcd1c에 대응하는 configure_sprite_pool로 활성화한다.

## 기본 콜백 경로

D0 상위word U, 하위word V를 사용한다. unsigned16 wrap을 적용하여(V-64)<640과(U+352)<1024일 때만 추가한다. D1 bit6은 지연 목록 선택이다. D5 하위word는 정렬 키, D7은 packed resource ID와 상위 제어값이다.

다음 생산 인덱스는(생산 끝+2)&0x1fe다. 읽기 인덱스와 다르면 해당 링 word가 가리키는12바이트 레코드를 할당한다. 일반 경로는 그 오프셋을 일반 쓰기 끝에 넣고 쓰기 끝을2 전진시킨다. 지연 경로는0x108f4e+지연길이에 넣고 길이를2 늘린다. 생산 인덱스는 두 경로에서 모두 전진한다.

레코드 long3개는 다음과 같다:
- `(D5.low16<<16)|((U<<6)&0xffff)`
- `D1&0xffffff07`
- `D7|((V<<23)&0xffffffff)`

비트 폭과 OR를 보존한다. D7에 이미 있는 상위bit를 좌표 대입으로 지우지 않는다. 콜백은 원본에서 가장 먼저 실행되므로 C++는 기본 RTS 콜백만 허용하고 다른 주소는 오류로 반환한다.

## 포화와 대기

다음 생산 인덱스가 읽기 인덱스와 같을 때 준비 끝도 읽기와 같으면 추가하지 않고 반환한다. 준비 끝이 다르면 그 값을 D4에 보관하고 읽기가 그 값에 도달할 때까지0xcda4에서 기다린다.

C++ status는 Accepted=0, Clipped=1, Full=2, Waiting=3이다. Waiting은 대기 진입 조건을 관찰한 결과다. 원본의 캡처된 D4나 재개 상태를 보관하지 않으므로 이 API를 단순 재호출하는 것으로 원본 대기 재개를 구현했다고 간주해서는 안 된다. 후속 비동기 스케줄러에 명시적인 대기 상태가 필요하다.

실패 시 RAM·status를 보존한다. 화면 밖인 경우는 원본과 같이 큐 필드 검사 전에 Clipped를 반환한다. 실제 쓰기 전에 인덱스·레코드 범위·지연 목록 공간을 검증한다.

## 검증

verify_sprite_producer.py는 임의의 초기 RAM8개에 대한 초기화와192개의 화면 경계·일반/지연·링wrap·Full/Waiting 조건을 원본 실행에 비교한다. 대기 조건은 원본PC0xcda4 첫 진입에서 정지하고 아직 RAM 변경이 없음을 확인한다. `--cpp`는 C++ 상태 코드와64KiB RAM 전체를 비교한다.

verify_sprite_pipeline.py는 초기화 후 통제된 슬롯 영역을 설정하고4회 연속 생성→준비→갱신을 수행한다. 초기 방향2개×초기 링 위치2개에서 원본과 C++의 각 단계 상태를 비교한다. 총124개 제출과32개 준비/갱신 단계의64KiB RAM·비디오 명령이 일치했다. 게임의 실제 vblank/IRQ 호출 주기를 대신하는 검증이 아니라, 상태가 다음 처리 단위로 전달되는 기능 검증이다.
