# 표시 링의 준비 전 정렬

프로그램 SHA256:29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f.
고정 ROM CPU 주소/파일 오프셋0x166bc..0x16bb8을 분석했다. 이 루틴은 준비 함수0x16bba가 지연 정렬0xce02 이후 호출한다.

## 대상과 순서

대상 링은0x108b34부터256개의 BE word 레코드 오프셋이다. 준비 끝0x108d36부터 생산 끝0x108d3a 직전까지를 정렬한다. 인덱스는 바이트 단위 짝수이고(index+2)&0x1fe로 wrap한다. 같으면 빈 구간으로 처리하고 scratch도 변경하지 않는다.

키는0x107f34+레코드 오프셋의 첫 BE word다. 원본은0x108d4e..0x108f4d의512바이트를 지우고, 각 키의 상위 byte 빈도를 짝수 byte에, 하위 byte 빈도를 홀수 byte에 쌓는다. 이256개 BE word를 차례로 누적합한다. 최대255항목이므로 하위 byte 빈도가256으로 넘어 상위 카운트를 바꾸는 경우는 유효한 링 범위에 없다.

그 다음 링을 뒤에서부터 순회해 하위 byte 누적 카운트를1 줄인 위치로 오프셋을 배치한다. 이 임시 배열은0x108f4e부터다. 임시 배열을 다시 뒤에서부터 순회해 상위 byte 누적 카운트를1 줄인 위치에 원래 링의 오프셋을 쓴다. 최종 결과는 unsigned16 키 오름차순의 안정 정렬이다. 같은 키의 순서는 원래 입력 순서를 유지한다.

## 지연 정렬과의 관계

0xce02의 지연 정렬은 선택한 레코드의 키를 이전 태그로 교체하고 일반 링에 합친다. 그 다음0x166bc가 전체 미준비 구간을 바뀐 키로 정렬한다. 두 함수를 동일한 정렬로 합쳐서는 안 된다. 이 루틴의 임시 배열은 지연 목록과 같은0x108f4e를 재사용한다. 호출부가 먼저 지연 목록을 비우는 순서가 중요하다.

## 검증과 계약

analyze_sprite_radix.py는 원본을 실행하고64KiB RAM 전체를 비교한다. 개수0/1/2/7/96/255, 오름차순/내림차순/동일키/부호경계/고정난수/중복오프셋의6패턴, 링 시작0/510의72조건이다. Python 모델과 원본의 scratch·임시 배열·링이 모두 일치하며 최종 오프셋 순서가 안정 unsigned 정렬과 같은지도 별도로 확인한다. `--cpp`는 동일 초기 상태의 C++ 실행도 비교한다.

C++ API는64KiB RAM, 짝수 링 인덱스0..510,12배수 레코드 오프셋0..3060을 요구한다. 중복 레코드 오프셋은 읽기만 하므로 허용한다. 입력 검증은 쓰기 전에 수행한다. 결과를 단순 std::sort로 재현하지 않고 scratch 메모리 효과까지 유지한다. CPU 레지스터·flags·스택·타이밍과 전체 준비 루틴의 동시 소비 대기는 계약에 포함하지 않는다.
