# `480bc` 프레임 helper 묶음 U4: 장면 갱신 `1a7a8` 계약

**상태: 메인 리뷰를 거쳐 확정(아래 메인 결정). 구현·검증 기록이 아니다.** 범위 근거는 `animation-machine-480bc-scope.md`의 U4, 진입 경계는 확정된 U2 계약(`animation-machine-scene-core-u2-contract.md`)의 `1a788` BSR 대상 `1a7a8`이다. Claude Opus 5.5 / high 분석 작업자가 canonical BE ROM(SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`, `extracted/program/maincpu.decrypted.be.bin`, fixed CPU 주소=file offset)을 capstone M68000으로 디코드하고 기존 관측 산출물을 읽기 전용으로 재생해 작성했다. [F]=원본 바이트 또는 기록된 산출물에서 확인한 사실, [I]=추론, [U]=미확인. 명령 단위 정답은 원본 바이트 자체다. 같은 루틴들의 typed host 재구성(`engine/src/scene_update.cpp`·`scene_map_transfer.cpp`, 문서 `scene-update.md`·`scene-path-execution.md`·`scene-map-refresh.md`)은 machine 실행부가 아니며 교차 확인 자료로만 쓴다.

메인 결정(Claude Opus 5.5, 원본 대조 리뷰 후): (1) 디버그 경로 `1b016..1b126`(`10f000` bit3/4)은 선택 D로 구현한다(block 시작 118; 전체 경로 seed 7개가 이 경로를 지나므로 guard하면 U2+U4 전체 frame 검증에서 빠진다). `1af12..1b112` ROM 표 읽기는 live bus로 한다. (2) X flag는 생산자와 소비자(`17258`, `17278`, `1b058`, `1b074`)가 같은 block 안에 있으므로 block 안에서 지역 계산하고 노출하지 않는다(SUBX의 Z 규칙 포함). (3) `43e08`/`43e22` stub은 U5(`1a470` 경로)로 미룬다. (4) path opcode index(`19e86`)는 U2/U3와 같은 계산 PC 정책을 따른다.

## 메인 결정 필요 항목

1. **디버그 경로 `1b016..1b126`(`10f000` bit3/bit4)**: 구현(선택 D, block 시작 118) 또는 guard(선택 G, block 시작 102 + 경계 `1b016`). [F] scene_frame 594 seed 중 68개(전체 경로 22개 중 7개: `173 177 183 185 187 189 191`)가 seed RAM `10f000`=`18`/`08`/`10`으로 `1b016`에 들어가고, 그중 4개(`129 153 592 593`)는 격자 draw(`3c0000` LONG 1280회)까지 간다. 선택 G면 이 seed들이 U4에서 rollback되어 U2+U4 전체 프레임 검증에서 빠진다. **작업자 권고: 선택 D.** 근거는 아래 "디버그 경로 선택".
2. **X flag 처리**: `1724c`/`1726c`(ADD.B 메모리→SUBX.L)와 `1b042`/`1b05e`(SUB.L→SUBX.L)는 X 생산·소비가 한 block 안에 있다. X를 block 지역 값으로만 계산하고 machine 상태(carry만 모델)에 노출하지 않는 안을 제안한다. 기존 `43e38` 실행부(`cleanup_coordinate`, ADD.W→ADDX.W)가 같은 선례다. 확인 필요.
3. **`43e08`/`43e22` 진입 stub의 소속**: [F] 두 stub은 `1a7a8` 정적 closure에서 도달하지 않는다(`43e08` 호출자 중 이 묶음 관련은 `1a4fa`=U5 `1a470`, `43e22`는 `16ff2`·`197d4`·`1a6ba` 등). U4에서 제외하고 U5에서 추가할지(권고), 아니면 U4에 미리 넣을지. [F] 기존 cleanup 라우팅 범위(`43dcc..43ea2` 포함)에 두 PC가 들어가므로 추가 시 `animation_machine_cleanup.cpp`의 case 또는 라우팅 분리가 필요하다(현재는 cleanup default의 `unsupported animation machine PC`).
4. **path opcode index 정책**: [F] `19e86` JMP는 `19e8a+sext(D7.W)`(D7.W는 BPL 통과로 `0..7fff`)이며 범위 검사가 없다. U2/U3 메인 결정과 같이 계산된 PC로 그대로 이동하는 안(지원 block 시작이면 실행, 아니면 기존 unsupported/홀수 PC 오류)을 제안한다. 예: `20`→`19eaa`(handler 00과 같은 PC, 실행), `2`→`19e8c`(거부), 홀수→홀수 PC 오류.

- **Path opcode index 정책(메인 결정 4)**: 원본처럼 `19e8a+sext(D7.W)`로 이동한다. 전용 오류는 두지 않는다.
- 폭·연산: 위 공통 규칙, MULU(무부호 16×16)·MULS(부호 16×16)·ASR.L #8(산술)·LSL.L #8, ADD.B 메모리 올림과 SUBX.L(X 결정 2), SUB.L/SUBX.L sticky Z, WORD wrap 산술(`19fae`·`19fd6`·`1a006`·`1a02c`·`18656`의 ASR.W #4), 08/14의 N-only BPL과 0c/10의 TST.W 뒤 BLE를 구분한다. MOVE.W (A2)+는 2 증가, MOVEM.L A1-A2·MOVE.L A1/A2 push·pop은 live stack LONG이다. BCLR 판정은 지우기 전 bit다. `3c0000` LONG 쓰기는 원본 1회=port 1개.
- 루프: `19e7e` path 보행(음수 opcode까지, 참 조건 포인터로 순환 가능), `1b084` 이중 DBRA(정확히 1280회). 상한은 기존 machine step 상한(1,000,000 block)에 맡긴다.
