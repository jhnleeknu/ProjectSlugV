# 68000 초기 오브젝트 목록과 디스패치

적용 프로그램 SHA256: 29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f.
아래는 고정 ROM 코드의 정적 해석이다. 에뮬레이터 실행 관찰이나 게임 전체 복원이 아니다. 함수명은 분석용 이름이다.

## 진입 경로와 주소
- 0x122/0x128/0x12e/0x134에 absolute JMP가 있고 각각 0x852/0xa74/0xc40/0xc36을 가리킨다. BIOS 호출 역할의 정확한 명칭은 아직 확정하지 않았다.
- 0x852는 A5=0x108000 설정과 상태 분기를 수행한다. 0x974 이후 초기화 경로는 여러 함수를 호출하고 0xa26에서 0x2aac로 이동한다.
- 0x09de..0x0a08 호출 중 0x2790이 아래 오브젝트 목록을 초기화한다.
- 0x09b8에서 PVC word_ff9에 0x1000, 0x09c0에서 word_ff8에 0을 쓴다. 이 시점 계산상 bank base는 0x200000이다. 이후 모든 구간에서도 동일하다고 가정하지 않는다.

## 초기 테이블: ROM 0x268a..0x270d
16바이트 레코드 8개와 4바이트 0 포인터 센티널이다. 레코드 구조는 RAM 주소(u32), 콜백 주소(u32), object+0x76/0x78/0x7a/0x7c에 복사할 네 u16이다. 모두 big-endian.

| RAM 노드 | 초기 콜백 |
|---|---|
| 0x100820 | 0x000e4a |
| 0x1008e4 | 0x00c52a |
| 0x1009a8 | 0x00270e |
| 0x100a6c | 0x00270e |
| 0x100b30 | 0x00270e |
| 0x100bf4 | 0x00270e |
| 0x100cb8 | 0x00270e |
| 0x100da8 | 0x00270e |

테이블의 네 설정 word는 이 버전에서 모두 0이다. RAM 주소는 테이블 값 그대로 보존한다. 초기 노드가 전부 일정 간격이라는 가정은 하지 않는다.

0x2790..0x27fe는 +4/+8 연결을 설정하여 첫 노드를 중심으로 순환 목록을 만든다. +0은 콜백, +8은 디스패치 다음 노드다. +4는 삽입 명령상 반대 방향 연결로 해석된다. +0xc와 +0x10도 초기화되지만 게임상 의미는 아직 미확인이다.

## 추가 슬롯 풀
0x2800..0x2848: RAM 0x100f5c부터 0x104c9c 미만에 stride=0xc4인 슬롯 80개를 초기화한다. 각 +0에 기본 콜백 0x270e, +8에 다음 슬롯을 넣고 마지막 +8은 0이다. 카운트 0x50과 비교하고 다르면 trap #15를 실행한다.
0x284c..0x287c는 바로 앞 RAM 0x100e98의 0xc4바이트를 비우고 별도 자기 참조 노드를 구성한다. 이 노드의 할당/회수 역할은 추가 조사한다.

## 디스패치: ROM 0x2aac..0x2ac7
- A6 = 0x100820; 최초 A7을 RAM 0x104ca4에 저장.
- 반복마다 A5 = 0x108000.
- A0 = long[A6+0]; JSR (A0).
- 콜백이 복귀하면 A6 = long[현재 A6+8].
- 0x2ab8로 반복.

콜백이 A6나 목록을 변경할 수 있으므로 호출 이전에 다음 포인터를 미리 읽으면 같은 동작이 아니다. 이 루프 자체에는 null 검사나 프레임 종료 조건이 없다. 임의의 C++ 안전 종료를 원본 동작이라고 구현하지 않는다. 전체 호출 규약 및 비지역 복귀 가능성은 아직 분석 중이다.

## 확인한 콜백 상태 전이
- 0xe4a 경로는 자체 노드의 +0을 0xe74로 변경한다(명령 0xe6e). 이후 함수 포인터를 통한 상태 전환이 일어나는 구조라는 근거다.
- 0xc52a 경로도 +0을 0xc560으로 변경한다(0xc55a).
- 기본 콜백 0x270e는 word[A6+0x10]이 0이 아니면 word[A5-0x335e]를 증가시킨 뒤 복귀한다. +0x10을 HP나 활성 플래그라고 명명하지 않는다.
- 초기화 helper 0x271c는 다른 세 helper를 호출한다. 그 전체 효과를 확인하기 전에는 부분 필드 초기화만으로 초기화 완료라고 취급하지 않는다.

## 추가 코드 영역 주의
0x1026..0x1095는 ROM 0x1342에서 읽은 word를 3비트 rotate-right하여 RAM 0x100000에 쓰고 그 RAM 코드를 호출하는 경로를 포함한다. ROM 바이트를 그대로 역어셈블하는 것만으로 이 코드를 해석할 수 없다. 코드 복사/변환 영역은 별도 재현 대상이다.

## 재생성
```sh
make setup-tools
.venv/bin/python tools/analyze_object_boot.py
```
리포트 artifacts/analysis/object_boot.json과 주소/원시 바이트를 포함한 artifacts/disassembly/*.json, *.asm을 생성한다. ROM 0x268a 테이블은 데이터로 분류되며 명령어로 디코딩된 외형을 코드 증거로 쓰지 않는다.
