# 오브젝트 필드 조건 분기 opcode0c

프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 고정영역 ROMoffset=CPU주소다.

0x4a02e의분기표항목이0x4a3b8 handler로연결된다. opcode뒤의형식은조건byte,선택자BE16,대상주소BE32로총명령8byte다.

- 4a3b8에서조건byte를읽고SNE로0/ff로정규화한다.
- 4a3bc에서선택자word를읽어ADD.W로2배하고4a76c 테이블의word를읽는다.
- 대상주소를읽은뒤오브젝트(A6)+테이블offset의byte를TST/SNE로0/ff로정규화한다.
- 두boolean이같으면대상주소로이동하고,다르면다음명령으로진행한다.
- 두경로모두4a276에서선택된실행포인터를상태(A0)+0에저장하고해석을계속한다. 따라서분기하지않아도저장포인터가갱신된다.

선택자테이블은여러명령에서공유한다. 이번에는4a76c의앞32word만실행검증했다. 테이블전체길이·유효선택자상한은미확인이다. 원본은ADD.W와signed word indexing을쓰므로큰선택자는메모리의다른곳을가리킬수있다. 이를유효게임명령으로일반화하지않는다.

## 검증

`.venv/bin/python tools/analyze_animation_branch.py`

32선택자 ×조건0/1/128/255 ×필드0/1/128/255 ×타이머0/1234/ffff =1536조건. 선택자offset은원본테이블에서읽었다. 분기대상에는28,fallthrough에는00/0을둔제어RAM스크립트를원본49fc6에서실행했다. 전체64KiB RAM·저장포인터·SCS로포착한반환carry가모델과일치했다. 따라서128과255도모두true이며1과동등하다는점을실행으로확인했다.

현재는원본해석근거와재현도구다. C++에서는0c를아직거부한다. 다음통합에는선택자테이블의추출범위를명시한런타임데이터와로더가필요하다. 원본offset목록을의미없는상수로소스에복사하거나검증한prefix를전체테이블이라고선언하지않는다. 실제0c사용스크립트의참조와선택자도추가확인대상이다.

## 후속 참조·범위 조사

`trace_animation_references.py`는고정영역의정렬된 `movea.l #script,A1; move.w #speed,D0; jsr49f8c` 후보와알려진opcode의제한된경로를목록화한다.32개초기화후보에서첫0c를찾았다. 패턴일치만으로자연실행도달성을주장하지않으며전체참조목록도아니다.

원본2baf4부터코드흐름을검토하면2bafc의오브젝트+7f 조건뒤2bb06에서A1=65f56,2bb0c에서D0=100을설정하고2bb10에서초기화49f8c를호출한다. 스크립트65f56은 `0c 00 001f 0006604c`로시작한다. selector31은테이블의offset7e byte를검사한다. fallthrough65f5e와분기쪽66054는모두미지원opcode14에도달한다. 이를건너뛰고전체스크립트지원이라고표시하지않는다.

다른후보3d2e2는스크립트3e808을지정하며첫명령은 `0c ff 002f 0003e832`다. selector47은offseta0이다. 양쪽후속opcode는18이며아직해석중이다. 이경우초기화패턴과데이터연결은확인했지만상위호출흐름은추가검토가필요하다.

### 필드 테이블의 후보 끝

4a76c에서145개word를읽으면마지막은4a88c의0082다. 바로다음4a88e는TST/조건분기/LEA로이어지는코드이며c9a6의JSR 대상이다. 따라서4a76c..4a88e를추출범위후보로삼을근거가생겼다. 패딩으로보이는0word도있으므로전체145개가실제게임에서사용되는선택자라고단정하지않는다.

실행검증을이145개word로확장했다.145×4조건값×4필드값×3타이머=6960조건에서전체RAM·carry가원본과일치한다. 앞32개검증을대체하는확장결과이며원본테이블을실행시읽는다. 소스코드에원본offset목록을내장하지않았다.

### 새로 확인한 opcode14 경로

4a408은opcode뒤byte를4배해4a500의함수포인터테이블을읽는다. 그뒤long operand를A0로읽고bank0으로전환한상태에서해당함수를호출한후원래bank를복원한다.65f5e의인자는함수선택1e와주소6431a다. 함수의작용과검증없이무시할수없는외부처리명령이다. C++0c 통합에더해이실제후속처리를복원해야자연스크립트연결이완성된다.

## C++ 데이터 리소스 통합

`step_animation_with_data`에MS5D창을제공하면0c를실행한다. 선택자×2의16bit wrap과signed indexing,필드offset의signed 확장,zero/nonzero비교,양쪽저장포인터갱신을구현했다. 조회값은코드에내장하지않고4a76c의MS5D창에서읽는다. 부족한범위나RAM밖필드주소는오류로처리하며이전RAM·carry를보존한다.

원본테이블145개와C++ MS5D로드경로를같은제어스크립트로비교한다. 단위테스트는selector8000의wrap alias,부족한창·중첩창·음수RAM범위·후속명령오류시rollback도검사한다. 현재추출창밖의word조회는묵시적0으로대체하지않는다.
