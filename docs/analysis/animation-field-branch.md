# 오브젝트 필드 조건 분기 opcode0c

프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 고정영역 ROMoffset=CPU주소다.

0x4a02e의분기표항목이0x4a3b8 handler로연결된다. opcode뒤의형식은조건byte,선택자BE16,대상주소BE32로총명령8byte다.

- 4a3b8에서조건byte를읽고SNE로0/ff로정규화한다.
- 4a3bc에서선택자word를읽어ADD.W로2배하고4a76c 테이블의word를읽는다.
- 대상주소를읽은뒤오브젝트(A6)+테이블offset의byte를TST/SNE로0/ff로정규화한다.
- 두boolean이같으면대상주소로이동하고,다르면다음명령으로진행한다.
- 두경로모두4a276에서선택된실행포인터를상태(A0)+0에저장하고해석을계속한다. 따라서분기하지않아도저장포인터가갱신된다.

선택자테이블은여러명령에서공유한다. 이번에는4a76c의앞32word만실행검증했다. 테이블전체길이·유효선택자상한은미확인이다. 원본은ADD.W와signed word indexing을쓰므로큰선택자는메모리의다른곳을가리킬수있다. 이를유효게임명령으로일반화하지않는다.

## 검증

`.venv/bin/python tools/analyze_animation_branch.py`

32선택자 ×조건0/1/128/255 ×필드0/1/128/255 ×타이머0/1234/ffff =1536조건. 선택자offset은원본테이블에서읽었다. 분기대상에는28,fallthrough에는00/0을둔제어RAM스크립트를원본49fc6에서실행했다. 전체64KiB RAM·저장포인터·SCS로포착한반환carry가모델과일치했다. 따라서128과255도모두true이며1과동등하다는점을실행으로확인했다.

현재는원본해석근거와재현도구다. C++에서는0c를아직거부한다. 다음통합에는선택자테이블의추출범위를명시한런타임데이터와로더가필요하다. 원본offset목록을의미없는상수로소스에복사하거나검증한prefix를전체테이블이라고선언하지않는다. 실제0c사용스크립트의참조와선택자도추가확인대상이다.
