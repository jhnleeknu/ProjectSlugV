# 전체 목표 대비 진행 현황과 남은 주 작업 단위 (2026-10-15 기준)

기준 커밋 `cc88bde`(PR #1 병합, D1 frame 구동기 포함). 작성은 메인 Claude Opus 5.5다. 전체 범위와 완료 기준은 `docs/GOAL.md`를 따르며, 이 문서는 그 범위를 줄이거나 바꾸지 않는다.

표기: [F] 저장소 기록·코드에서 센 사실, [I] 추론·추정, [U] 미확인. 단위 수와 진행률은 모두 [I] 추정이며, 분석이 진행되면 다시 센다.

### 1.1 엔진·로직의 원본 대응 범위
- [F] animation machine에서 routing이 연결된 원본 코드는 534개 구간, 154,612바이트(약 155KB)이며 모두 고정 프로그램 영역 `0..fffff` 안이다.
  - 센 방법: `engine/src/animation_machine.cpp`의 `next.pc` 조건식(범위 653개, 단일 PC 77개는 2바이트로 계산)을 인접·중첩 구간끼리 병합했다.
  - 이 수치는 routing 범위다. 그 안의 모든 경로가 원본 비교로 검증됐다는 뜻은 아니다.
  - 그 밖에 메뉴·팔레트·사운드 큐·스프라이트 큐·입력·인터럽트 task 등 초기 함수 단위 API가 별도로 있다.
- [U] ROM 전체 코드 중 C++로 옮긴 비율은 측정하지 않았다. 고정 영역에는 자료도 섞여 있어 바이트 비율로 대신할 수 없다.
- [F] 원본과 일치가 증명된 연속 실행 범위는 다음과 같다(`docs/reviews/0262-frame-driver-d1.md`).
  - 시작점: 스테이지 area 진입 시점의 자연 fixture seed 137개(catalog 기록 기반 host 쓰기 포함).
  - 조건: 입력 없음(`ff`), raster 0, controller 생략(D1), IRQ·BIOS 선언.
  - 결과: 136개 seed가 400 frame(약 6.7초)을 완주했고, frame별로 비교한 54,400 frame이 모두 일치했다(불일치 0). 나머지 1개(case 141)는 원본에서도 frame 0의 `odd-pc`에서 멈춘다.
- [F] 이 범위에 들어가지 않는 것:
  - 플레이어 조작
  - 대부분의 적·보스
  - 다른 스테이지 진행
  - 부팅·타이틀·데모
  - 사운드 재생(Z80)
  - 실제 렌더링
  - 에뮬레이터 화면·사운드 대조
- [I] 완료 기준(GOAL §7) 대비 진행률은 약 15~20%로 본다.
  - 지금까지 구현한 것은 실행 경로가 고정된 공통 엔진(scheduler, frame head, stage controller 일부, 공유 객체 core)이다.
  - 앞으로의 플레이어·적·보스·스테이지 코드는 양이 더 크고, 입력과 스테이지 진행이 있어야 실행된다.

## 3. 핵심 선행 기반: 입력·스테이지 진행 관측

- [F] 지금 seed는 area 진입 상태에 host가 쓴 fixture다. 플레이어 입력과 스테이지 이동이 없어 C·D 영역 코드가 거의 실행되지 않는다.
- [I] 다음 방법을 쓴다. BIOS 없는 부팅을 선언하거나 boot 상태 fixture를 만든 뒤, demo replay(`104cd4`=1 경로, ROM replay stream `f01fe..`)나 선언 입력 스크립트로 스테이지를 진행시켜 관측한다.
  - 이 기반이 C·D·E의 seed 공급원이 된다.
- [I] 플랫폼 제약이 있다. 역사 native 산출물은 Unicorn 라이브러리 SHA 때문에 다른 OS에서 바이트 재현이 되지 않는다.
  - 새 관측 도구는 처음부터 플랫폼 종속 필드를 비교 대상과 분리해 기록한다.

## 4. 권장 순서

1. A(controller·IRQ): frame 전체를 선언 없이 실행한다.
2. §3 입력·스테이지 진행 관측 기반을 만든다.
3. C(플레이어) → D(스테이지 단위로 적·보스·맵)로 확장하고, I(리소스)를 병행한다.
4. F(사운드)와 G·H(렌더링·실행 프로그램)는 A 이후 독립적으로 병행할 수 있다.
5. E(부팅·타이틀)로 부팅부터 플레이까지 연결한다.
6. J(에뮬레이터 대조), 마지막으로 K(최종 정리)를 한다.

B는 언제든 끼워 넣을 수 있다. 다만 G3 C++ 검증기는 기존 F4 인수의 남은 항목이므로 A와 함께 처리하는 것이 좋다.

- 완료할 때마다 이 문서의 표를 갱신한다(완료 표시, 단위 수 재추정).
