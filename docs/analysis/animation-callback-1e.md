# 애니메이션 외부 처리 명령14 / 선택자1e

프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`. 아래주소는고정영역 CPU주소=ROMoffset이다.

14 handler4a408은함수선택byte를4배하여4a500의long테이블을읽는다. 선택1e의항목은4a578이며값은2b3fa다. 이어명령의long operand를A0로읽는다. 상태A0와명령A1,bank shadow를스택에보관하고bank0으로전환한뒤선택한함수를호출한다. 반환후스택을복원하고4a276에서다음명령주소를상태포인터에저장한다.

2b3fa는다음과같이작동한다.

1. D0을0으로지운뒤오브젝트(A6)+7d의byte를읽는다.
2. word를두번2배하여index×4를만든다. byte전체범위0..255이므로이연산은signed index 경계를넘지않는다.
3. A0+index×4의long을오브젝트+78..7b에복사하고반환한다.

즉선택자1e자체는테이블주소를인자로받는32bit값복사다. 이값을상태번호·충돌정보·프레임주소등으로명명하려면후속읽는코드와테이블경계를추적해야한다. 값이포인터처럼보인다는이유로용도를단정하지않는다.

실제조건분기스크립트65f56의fallthrough65f5e에는 `14 1e 0006431a`가있다. 따라서이경로의테이블기준주소는6431a다. 분기후14를무시하면오브젝트+78이원본과달라진다.

## 실행 검증

`.venv/bin/python tools/analyze_animation_callback.py`

원본14/1e명령과00/0대기를포함한제어RAM스크립트를49fc6에서실행했다. index0..255 ×timer0/1234/ffff ×초기bank shadow0/3 =1536조건에서전체64KiB RAM과반환carry가모델과일치했다. opcode14의다음명령주소저장,음수타이머의후속재해석,복사값을함께검증한다. carry는RTS뒤검증stub의SCS로포착한다.

원본해석기진입은bank shadow를0으로설정하므로이검증은handler가비영bank에서독립호출되었을때의복원을증명하지않는다. PVC장치의실제bank전환타이밍도검증범위가아니다.

byte전체인덱스의주소계산을검사하기위해고정ROM의6431a+index×4를읽었다. 이1024byte전체가하나의논리테이블이라고판정한것은아니다. 실제스크립트에서사용하는인덱스집합과테이블경계는미확인이다. runtime 포장시이를분리하여선언해야한다.

C++ opcode14는아직미지원이며다른함수선택자의행동은이분석과독립적이다. 다음통합은선택자필드테이블과주소기반데이터조회리소스를명시적으로받도록실행기를확장하는것이다.

## C++ 데이터 리소스 통합

14/1e는MS5D의불변조회창을사용한다. operand주소+index×4가고정ROM범위와제공창안에들어가야하고오브젝트+7d/78..7b도RAM안에있어야한다. 다른callback선택자는명시적오류다. 성공후다음명령주소를상태포인터에저장하고해석을계속한다.

`analyze_animation_callback.py --cpp`는원본조회와C++ MS5D로드경로1536조건의전체RAM·carry를비교한다. 이는조회창에포함된모든byte를논리적으로하나의테이블이라고확정하는검증이아니다. 자연스크립트의후속10/18등명령은별도복원대상이다.
