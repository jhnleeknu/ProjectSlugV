프로그램 SHA256 `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.

`tools/analyze_main_callback_refs.py`는 fixed ROM 첫1MiB의 모든 짝수 위치에서 한 명령 후보를 해석하고 `$76(a6)` 참조를 기록한다. 총1,101후보(write295/read597/LEA32/other177), 즉시 MOVE.L 값13종류가 나왔다. 이 위치들은 데이터나 명령 중간일 수 있고 A6가 메인 오브젝트라는 보장도 없다. 따라서 모두 메인 콜백이라고 분류하지 않는다. 알려진 f30 읽기만 기존 메인 제어 흐름의 정렬 근거를 가진다.

메인 에이전트가 확인한 fixed e40..e48은 A0를 A5−776a, A6를 A5−7766에 저장한다. A5=108000이면 각각100896/10089a이며, 부팅 첫 노드100820의 +76/+7a다. `object-dispatch.md`의 부팅 노드와 대응한다. 이 함수의 본문 의미는 콜백/문맥 등록과 일치하지만 이번 조사에서 자연 실행 호출을 관측하지 않았다. 30a18/30c2a가 +76에 저장하는31c92는 그 위치의 데이터형 패턴과 다른 오브젝트 사용 가능성이 있어, f3c 호출 대상으로 확정하지 않는다. 다른 +76 저장 역시 개별 자료구조 확인이 필요하다.

## fixed 이후 c64 등록 후보

기존 fixed1MiB c64 직접 호출 조사에 이어 `tools/analyze_task_queue_banked_refs.py`로 ROM offset100000..800000을 조사했다. 3,670,016개 짝수 시작에서 c64 절대 JSR/JMP 후보는0개였다. BE32 `00000c64`의 값 일치는8곳: 2315a0,234eda,248a1a,24cb54,24cc14,251154,2511d4,4086bc. 이들은 ROM 오프셋이며 CPU 주소·코드·포인터로 확정하지 않는다.

PC상대 BSR/JSR/JMP도 명시적인 가상 좌표 두 방식에서만 산술 검사했다. 실제 CPU200000..2fffff window라면 signed16 상대분기는 fixed c64에 닿을 수 없다. 하지만 이 계산은 ROM chunk의 실제 매핑을 확정하지 않는다. 간접 호출, RAM 코드, 자연 실행 도달성은 남아 있다. 결과가0이라는 이유로 작업 큐를 미사용으로 선언하지 않는다.
