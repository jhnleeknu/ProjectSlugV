# 지연 표시 큐 정렬과 태그 갱신

프로그램 SHA256:29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f.
고정 ROM CPU 주소0xce02..0xce60이며 파일 오프셋과 같다. A5=0x108000을 전제로 한다.

## 확인된 메모리 효과

- RAM0x10914e: 지연 목록의 바이트 길이. 목록은0x108f4e부터 BE word 레코드 오프셋을 담는다.
- RAM0x109150: 태그. 함수는 먼저 이전 값을 보관한 뒤 입력D0 하위16bit로 교체한다. 빈 목록에서도 이 교체가 일어난다.
- RAM0x108d38: 일반 링의 다음 쓰기 바이트 인덱스. 목록은0x108b34부터512바이트다.
- 레코드는0x107f34+오프셋이며12바이트. 첫 BE word가 이 정렬 경로의 키다.

함수는 지연 목록의 마지막 항목부터 앞쪽으로 순회한다. 현재 키가 앞쪽 키보다 크거나 같으면 앞쪽 슬롯에 현재 선택 오프셋을 쓰고 앞쪽 항목을 새 선택으로 바꾼다. 최소 unsigned16 키의 항목을 선택하여 첫 word를 이전 태그로 교체한 뒤 일반 링에 append한다. 다음 링 인덱스는(index+2)&0x1fe다. 남은 길이를2 줄여 반복하고 마지막에 쓰기 인덱스를 저장하며 지연 길이를0으로 만든다. 목록 내부의 교환 결과도 원본 메모리 효과이므로 정렬 결과만 비교해서는 충분하지 않다.

정렬은 signed 비교가 아니다. 동일 키의 순서는 원본 교환 알고리즘으로 보존하며, 별도 정렬 라이브러리의 동작으로 추정하지 않는다. 키 교체는 선택한 항목에만 적용되고 나머지10바이트는 유지된다.

## 검증과 C++ 계약

analyze_sprite_sort.py는 원본 초기화0xccd6와 생성0xcd58을 실행해 지연 레코드를 만든다. 개수0/1/2/7/31/96/200/255, 오름차순/내림차순/동일키/부호경계/고정난수 패턴, 링 시작0/0x1fc의80조건을 실행한다. 원본0xce02의 RAM64KiB 전체가 명령에서 도출한 모델과 일치한다. `--cpp`는 같은 초기 상태로 C++ sort_sprite_queue를 실행하여 다시 원본과 전체 RAM을 비교한다.

C++ 입력은64KiB RAM, 새 태그다. 지연 목록 길이는 짝수0..512, 링 인덱스는 짝수0..510, 레코드 오프셋은12의 배수0..3060이며 중복되지 않아야 한다. 최대512는 자료 저장 공간의 상한이며 실제 동시 큐에256개를 넣을 수 있다는 주장은 아니다. 잘못된 상태는 쓰기 전에 거부한다. 호출 스택·레지스터·CPU flag는 RAM 계약 밖이다.

## 아직 미확인

생성0xcd58은 다음 링 인덱스가0x108d34와 같으면0x108d36을 읽는다. 두 값이 같으면 추가 없이 반환하고, 다르면0x108d34가 방금 읽은 값에 도달할 때까지 대기한다. 이 분기에는 소비자와의 동시 진행이 필요하므로 동기 C++에서 임의로 spin하거나 새 레코드를 덮어쓰지 않는다. 일반/지연 큐의 전체 스케줄·콜백 효과·실제 프레임별 정렬 호출과 새 태그의 상위 의미는 다음 분석 대상이다.
