# c8c 인터럽트 작업 경로의 실행 근거

원본 프로그램 SHA256: `29112a94b5c073de95919ab4efbc75427287739eab794ef442d2aa7c886c860f`.
고정 ROM에서 CPU 주소와 프로그램 오프셋은 같다. RAM 오프셋은100000 기준이다.

`tools/analyze_interrupt_flow.py`는 원본c8c를 Unicorn M68000으로 실행한다. 코드를 패치하거나 의존 함수의 반환을 위조하지 않는다. 이 도구는 C++ 인터럽트 구현 비교가 아니라 다음 구현 범위를 결정하는 원본 실행 관측이다.

## 진입 구간

c8c는0019.bit7을 세운 뒤 이전 값이1이면 즉시 반환한다. 따라서 재진입 경로는0019의 다른 비트를 지우지 않고 신호를 늘리지 않는다. 이전bit7이0이면0016을byte 증가한다. overflow이면ff로 되돌리고 watchdog 쓰기는 생략한다. 그 외에는 들어온D0의하위byte를300001에 쓴다. 이후cb0에서bbe를 호출한다.

5,632조건을cb0 직전 또는 실제rts까지 실행했다. 모든 signal byte와 모든 guard byte를 포함하며 전체64KiB RAM을 기대값과 비교했다. 재진입 즉시 반환2,304회, watchdog 쓰기3,188회를 확인했다. 이 구간만 실행한 결과를 인터럽트 전체 완료로 표시하지 않는다.

## 제한된 전체 반환 경로

0014=0,001b=0,d68c.word=0,사운드head=tail=0인 조건에서는 실제bbe→3cac→48156→3cb2→d4e를 거쳐c8c 전체가 반환한다.864조건에서 전체RAM과 순서 있는 포트1,512회가 기대값과 일치했다. 신호0/254/255, guard0/1/7f,fd82의0/1,status0/1/2/ff,f001.bit4와 사운드 우선 명령3/7f를 조합했다.

끝의d4e는0019 전체byte를0으로 만든다. 최초 신호가255여도 이 정상 반환 경로를 실행한다. f001.bit4에 따른3a0001 쓰기의 값은 상수가 아니라 그 시점D0.byte다. fd82=1이면bbe가 조기 반환하여 진입D0.byte가 남고,fd82=0 및0014=0이면bbe가 D0.byte를0으로 바꾼다. 실제 포트 기록으로 이 차이를 확인했다.

## 실제 도달한 미완료 의존성

각 조건에서 원본 명령을 계속 실행한 뒤 지정한 의존 함수의 첫 명령 직전에 멈췄다.

- fd82=0,fdaf=2,0014=1: a2c의 상태/credit 관련 처리 진입.
- 001b.bit7=1:72fa 진입. 이후 작업·렌더링 경로는 이 실험에서 실행하지 않는다.
- d68c.word=1:48156이 이를2로 바꾸고 D0.word=19c1로3af8 진입. D0의 상위word는 기존 값을 유지했다.
- 나머지 quiet 조건:3cb2의 사운드 status 읽기 직전.

전체 바깥20c vector handler, BIOS 처리, 활성 팔레트·스프라이트 작업, 사운드 생산과 작업 스택 복구, 실행 도중 중첩 interrupt와 자연 발생 주기는 아직 검증하지 않았다. 신호 증가를 게임 루프에 자동 주입하는 근거로 이 제한된 실험을 확대 해석하지 않는다.
