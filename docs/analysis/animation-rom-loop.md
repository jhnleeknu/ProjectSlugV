## 참조와 경계

0x1e67a는오브젝트+20에00ca를설정하고,0x1e692는style bit6을세운다.0x1e6a6에서A1=6f1e2,0x1e6ac에서D0=100을설정한뒤0x1e6b0에서초기화49f8c를호출한다. 추출기는 이명령바이트를검증한다. 초기화는상태포인터와감소량을설정한다. 상위게임흐름의자연도달성까지실행검증한것은아니다.

6f1e2의스크립트는5개의draw/wait쌍(각10byte)과6byte 절대점프로구성된다. 첫draw의ID7ff800은제출생략값이다. 나머지ID operand52800/53000/53800/54000에그룹ca를OR해실제합성ID를얻는다.6f214의08명령이6f1e2로되돌아간다. 이자기참조를근거로56byte범위를추출한다. 임의로보이는바이트패턴이나0종료만으로경계를정하지않았다.

## opcode08

0x4a3ac은opcode뒤1byte를건너뛰고BE32 주소를읽어A1로옮긴다.0x4a276에서그주소를상태포인터에도저장한뒤해석을계속한다. C++는실행cursor뿐아니라다음대기에서되돌아갈pointer변수도갱신한다. 분기후실제fetch는현재MS5A범위안이어야한다. 외부리소스로의분기는아직연결하지않았다.

## 추출·실행·검증

```sh
.venv/bin/python tools/pack_animation.py
make all test
.venv/bin/python tools/verify_animation_pipeline.py --rom-script
```

MS5A는원본명령과주소를보존하고C++로더가CRC·길이·고정영역범위를검사한다. `step_animation_resource`가리소스와RAM을읽어실행기에전달한다. 의존합성리소스네개는기존MS5C로더와준비/갱신경로를사용한다.

원본은복호화ROM의6f1e2를직접읽고C++는추출MS5A를읽는다. 초기타이머0/ffff,감소량128/256,방향0/128의8시퀀스에서12회씩실행했다.96호출·192준비/갱신단계의전체RAM·carry·비디오쓰기가일치했고반복점프를포함한여섯상태포인터를관찰했다. 원본호출부의감소량은256이며128은경계검증용이다.

오브젝트위치·반전·팔레트는제어된검증상태다. 호출부의팔레트할당8ebe와ID8cd는정적으로보이지만최종팔레트바인딩·게임내장면·실제프레임주기까지증명하지않는다. 이단계는자연스크립트하나의엔진연결이며전체애니메이션카탈로그나전체게임완료가아니다.
