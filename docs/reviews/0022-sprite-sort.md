# 지연 표시 정렬 리뷰

대상:cb25549 이후 변경. 이전 turn은 줄별 스프라이트 선택 구현·검증·커밋으로 진척이 있었다.

메인 에이전트가0xccd6..0xce60을 역어셈블해 정렬의 교환·태그·링 상태 효과를 추론하고 원본 CPU70조건으로 먼저 검증했다. 확정 규약을 서브에이전트에 위임하고 실제 구현을 읽은 뒤255개 큐 경계까지80조건으로 확장했다.

- signed 비교나 일반 라이브러리 정렬을 쓰지 않는다. 원본 swap 경로와 목록 내부의 변경까지 재현한다.
- 입력D0 하위word는 현재 태그가 되고 이전 태그가 선택된 레코드 첫word에 기록된다. 빈 큐도 태그는 갱신한다.
- index는byte단위로2씩 증가하며0x1fe mask로wrap한다.
- 목록 길이·인덱스·레코드범위·중복을 쓰기 전에 검증한다. 레코드·두 목록의 주소 범위는 겹치지 않는다.
- `analyze_sprite_sort.py --cpp`:80조건, 각64KiB RAM 전체가 원본0xce02 실행과 일치한다.
- 기존 `make test` 통과. 추가 큐 API 테스트에서 잘못된 입력의 상태 보존과 저장 상한을 검사한다.

레지스터·스택과 소비자 동시 실행, 호출 태그의 게임 상위 의미는 검증하지 않았다. 전체 게임 완료가 아니다.
