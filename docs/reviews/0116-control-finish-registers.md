# 메뉴 반환 꼬리의 D1/D3 리뷰

대상 기준 커밋: `974ae2c`.

메인이9302..932e,928e..92cc,3918 및386e..38e6 원본을 확인했다. 종료문구9079의 위치제어는38ce의MOVEQ0,D3으로 상위word까지 지운다. 기존 line반환만으로는 이변화를표현하지못했다. 반면 글꼴제어는 D1.word안에서만 작동하므로 상위16비트는 보존한다. 원본테이블렌더러의 해당 범위에서도 D3변경이 없음을 확인했다.

`trace_table_fixed_text`에 최종style과전체D3출력을추가하고, 파서의 실제위치제어실행여부를기록했다. native주소만보고상위word를강제로지우지않으므로 위치제어없는스크립트도올바르게동작한다. `finish_control_menu`는후보레지스터를성공시에만반영한다. CLI/API모두기존style/line과전체레지스터의lowword일치여부를확인한다.

- `make -j3 all test`: Python73개 및 C++전체검사 통과, 경고없음. 로그 `artifacts/control_finish_registers_build_test.log`.
- 단위검사는 전체D3초기화, 글꼴변경후D1상위보존, 글자없는종료제어문자, 위치제어없는D3상위보존 및 늦은오류의레지스터롤백을확인했다.
- `.venv/bin/python tools/verify_control_finish_registers.py`: 원본880조건, 실제9079출력118회/포트1,180개, 오류63조건 통과. 전체RAM/전체D0,D1,D3/순서있는포트를비교했다.
- 메인리뷰에서 3개40회연속꼬리검증을독립레지스터입력에서이전CLI의전체D1/D3반환값을넘기는방식으로강화했다. RAM도이어전달하며 D0는명시적프레임반환조건이다. a370본체를연속실행한검증으로해석하지않는다.
- 고정원본ROM불변을확인했다. 잘못된위치제어리소스는오류보존검사에만사용하며원본실행은변조하지않았다. 실제출력에는정규control_pause.ms5d를사용했다.
