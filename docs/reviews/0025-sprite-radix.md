# 표시 준비 전 radix 정렬 리뷰

대상:b850208 이후 변경. 이전 turn은 큐 갱신 dispatcher 구현·원본 검증·커밋으로 진척이 있었다.

메인 에이전트가 원본0x166bc..16bb8을 분석해 두 byte histogram과 안정 배치를 도출했다. 60조건 원본 비교 후 확정 규약의 C++ 구현을 위임했다. 이후 중복 레코드를 추가해72조건으로 확장하고 diff·CLI·테스트를 리뷰했다.

- 첫 단계 low byte, 두 번째 high byte이며 두 단계 모두 역순 순회와 누적합 감소를 사용한다.
- 비어 있으면 histogram과 임시 배열을 변경하지 않는다.
- 최대255개에서 byte 카운트가 넘치지 않으며 packed word 누적합의 endian/폭을 유지한다.
- 중복 오프셋은 허용한다. 레코드 자체는 바뀌지 않고 참조 배열만 정렬된다.
- 기록 전에 전체 ring 범위/offset을 검증해 실패 시 원본RAM을 보존한다.
- `analyze_sprite_radix.py --cpp`:72조건64KiB 전체 원본 일치 및 안정 unsigned 순서 검증.
- 기존 지연 정렬80조건 원본 비교 통과. make all test 통과.
- C++ 테스트는 삽입 정렬·개별 빈도 계산이라는 별도 oracle로 최종 ring·scratch·미사용 메모리 보존을 검사한다.

전체 준비 함수의 소비자 대기와 일반 emission 연결은 아직 미완료다. 정렬 분석으로 전체 프레임 또는 게임 동작 완료를 주장하지 않는다.
