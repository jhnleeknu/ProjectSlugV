# 메뉴 추가·스택 다시그리기 전체 레지스터 리뷰

대상 기준 커밋: `f035167`.

메인이 원본 a0a0..a1e0 및 a6da..a708을 확인하고 API 구현을 담당했다. a0c8/a104의 D1 전체 저장·복구와 D3의 연속 전달을 구분했다. 하위 메뉴 구성은 진입 Y로 style 측정을 시작하고 D1 상위 word를 복구한다. 스택 다시그리기는 오래된 슬롯부터 테두리·전체 텍스트 출력을 순서대로 연결한다.

- 선택적 전체 D1/D3 출력은 기존 호출 방식을 유지하며 입력 lowword 모순을 거절한다. 후보 RAM/포트/레지스터는 성공 시에만 반영한다.
- 테두리 종료 line을 별도로 계산하던 코드를 제거하고 실제 테두리 API의 D3 반환값을 사용한다.
- 서브에이전트의 CLI·단위 검사·독립 원본 비교기를 메인이 실제 diff와 함께 검토했다. 새 레지스터 모드 외 기존 stdout 계약은 유지했다.
- 다시그리기 오류 검증의 원래 descriptor0x200은 테두리 전에 거절되므로 late failure라는 설명이 잘못됐다. 유효 descriptor와 잘못된 항목 수로 바꾸어 테두리 준비 뒤 텍스트 검증 실패를 확인했다.
- `make -j3 all test`: 종료 0, Python 73개와 C++ 전체 검사 통과, 경고 없음. 로그 `artifacts/menu_stack_redraw_registers_build_test.log`.
- `.venv/bin/python tools/verify_menu_stack_registers.py`: 원본 544조건, 포트 135,264개, 출력 보존 오류 검사 27조건 통과. 보고서 SHA256 `cf1f98e6c894477560cb2936cef2a557d50252e07f96670e60238d5bd6690705`.
- `.venv/bin/python tools/verify_menu_redraw_registers.py`: 원본 698조건, 포트 428,143개, 출력 보존 오류 검사 7조건 통과. 보고서 SHA256 `68711c1438609585d43f68612cb6300b3cba8c042a0e817d9ad1c05262de1159`.

메뉴 추가는 원본 main/debug/area/group 부모·자식과 빈 스택, 숨은 부모·보이는 부모, 두 렌더러를 비교했다. 두 번의 4단계 추가 흐름은 실제 CLI 반환 RAM/레지스터를 이어 쓴다. 다시그리기는 3,377회 실제 스테이지 콜백의 순서와 진입 stack S−28을 확인했으며 6프레임에서 실제 CLI 출력값을 이어 쓴다. 검증은 원본 첫 1MiB 불변과 실제 MS5D 리소스를 확인한다.

이 변경은 정상 반환하는 a0a0와 a6da 경계의 RAM·D1/D3·포트에 대한 것이다. 전체 a370과 상위 이벤트의 레지스터 전달은 다음 단계다. 다른 레지스터·SR, 가득 찬 스택의 잘못된 원본 복귀, 외부 스택 잔여값, 실제 화면 픽셀·인터럽트 타이밍 또는 전체 게임 복원 완료를 주장하지 않는다.
