# IRQ 신호·프레임 대기 연결과 두 번째 IRQ 리뷰

대상 기준 커밋: `094ef34`.

메인이29c..2d6의 전체 원본 명령을 확인하고 활성 콜백/비활성 acknowledge 및2b6 복구를 구현했다.20c와 달리 A5만 저장·복구하므로 다른 callback 레지스터 변경을 보존한다. 기본RTS와 실제 스택을 공유한다.

- `make all test`: Python73개 및 C++ 전체 검사 통과, 경고 없음. 로그 `artifacts/raster_irq_build_test.log`.
- `.venv/bin/python tools/verify_raster_irq.py`: 원본386조건, MMIO314개, 스택 쓰기441개와 오류/별칭23조건 통과. 전체 RAM/스택/16레지스터를 비교했다.
- 새 CLI 모드의 문자열은 추가됐지만 인자 검사와 API 분기가 연결되지 않은 오류를 검증에서 발견했다. 메인이 실제 소스를 확인해 명시적인 분기로 수정하고 전체 테스트와 원본 검증을 재실행했다.
- raster 보고서 SHA256 `80591506798ab679b7a31376b4d5e41b40e69326a92498d7d0b9b2e5547ee91d`.

별도 연결 검증은 기존 C++ 서비스/메인 poll을 같은 RAM으로 사용한다. 원본 IRQ 서비스279회와 메인 poll294회, 포트1,070개가 일치했다. 원본 서비스255회에 의한 신호 생산과 실제 메인 소비를 확인했으며 초기0/254 외의 RAM16 직접 주입은 없다.

- `.venv/bin/python tools/verify_interrupt_frame_flow.py`: 573조건 통과. 전체 RAM/읽기 횟수/포트 및 callback·controller 경계를 비교했다.
- 기다리는 메인 문맥은 IRQ 후 호스트가 복구한다. 각 다음 프레임의 poll 레지스터도 명시적 입력이며, ec4와 콜백 본문을 실행한 전체 메인 루프는 아니다. 이 한계를 코드/보고서/분석 문서에 명시했다.
- flow 보고서 SHA256 `348041d00751e20595f0db2b2e79eabdc7d8317bce7732eb74a361c664cdd5a6`.

모든 원본 바이트는 불변이다. SR/RTE/BIOS·자연 시간축과 전체 부팅은 미완료다. 이번 계약과 검증 범위에서 미해결 통합 차단 문제는 없다.
