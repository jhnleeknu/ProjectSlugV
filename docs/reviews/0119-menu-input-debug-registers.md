# 메뉴 입력·헤더·디버그 콜백 레지스터 리뷰

대상 기준 커밋: `b3c27e8`.

메인이 a472..a562,9430..9464,9aa8..9b26,9f36..9fc2 명령을 확인했다. 입력 결정의 D1은 a474에서 전체0으로 초기화된 뒤 활성P2 입력byte를 담는다. 헤더는9086의D1변경을전달한다. debug draw는9f36에서D1상위를지우고9f78/9332로style을선택하며, 그리지않는event는전체D1/D3를유지한다.

- 세 API에 선택적 레지스터 출력을 추가했다. 기존 호출은 유지하고 오류 시 레지스터도 보존한다. 디버그 API는입력D3.lowword와기존line의일치를확인한다.
- 기존입력/헤더 CLI는새옵션사용시에만D1을출력한다. 새dispatch_debug_menu CLI는정규메뉴/폰트MS5D를읽고9aa8콜백만검증할수있게한다. 이CLI의A2문맥은현재슬롯이다.
- `make -j3 all test`: Python73개와 C++전체검사 통과, 경고없음. 로그 `artifacts/menu_input_debug_registers_build_test.log`.
- 단위검사는 D1전체초기화와byte변경 차이, 디버그 그리기/닫기의보존차이 및오류롤백을확인했다.

이작업은 a370전체프레임의반환값을완성한것이아니다.9b3e의항목argument설정과9d3a의숨은행D1byte변경을후속텍스트통합근거로남겼다. stage동적콜백과메뉴텍스트전체의D1/D3반환은아직남아있다.

- `.venv/bin/python tools/verify_menu_input_debug_registers.py`: 원본3,988조건(입력1,380/헤더640/직접디버그1,968), 포트2,952개, 오류44조건 통과. RAM전체와API레지스터출력, 입력동작파일과순서있는포트를비교했다. 입력/헤더의D3불변도별도확인했다.
- 입력은원본동작분기직전에정지하며디버그는A2=current로9aa8에직접진입한다. 실제9b3e까지실행한것으로주장하지않는다. 원본첫1MiB와메뉴/폰트리소스를검증했다.
- 메인리뷰에서반복검증이동등성을확인한원본값을다시전달하던부분을실제CLI파일/JSON반환값으로변경했다.6개디버그반복흐름에서이를확인했다.새CLI의EVENT범위및입력/출력동일경로·하드링크·심볼릭링크거절도보강했다.
