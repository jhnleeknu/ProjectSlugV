# 디버그 설정 콜백과 글꼴6b 리뷰

대상: `fa5f4d8` 이후 변경.

메인 에이전트가 callback9aa8, 좌표9f36/스타일9f78, wrapper9332, glyph renderer e84c8의6b 분기를 읽고 bit 연산, 좌표 연산 폭, 출력 순서, DE/DF 및 @ 문법을 확정했다. 서브에이전트의 글꼴 구현과 메뉴 API 전달 코드를 diff로 검토했다.

- 원본 lookup 표를 작은 별도 MS5D로 추출하여 C++가 읽는다. 하드코딩 글리프나 PNG 대체가 아니다.
- debug event5를 일반 항목 출력 뒤에 연결했다. 원본과 같은 비가림 출력이며 폰트 포인터가 이동/부모 출력까지 전달된다.
- line 출력은 일반 문자 측정에서 추정하지 않고 실제 6b parser의 소비 결과를 반환한다. @ 문법이 제어문자처럼 보이는 byte를 소비하는 경우를 보존한다.
- bit 표가16 이상이면 미지원 범위로 거절한다. 실제 ROM 표는 모두0..15이고, 존재하지 않는 상위 register 상태를 추측하지 않는다.
- 기존 API 호출은 선택적 font 기본값NULL로 유지된다. 필요한 font가 없는 debug 경로만 명시적으로 실패한다.

검증: 원본/C++ debug2,100조건, 글꼴104스트림, 부모 이벤트975와 기존문자288 회귀, 전체 테스트 통과. 단위 검사에서 bit15, 자식 출력 후 final line, 리소스 누락과 중간 실패 보존을 확인했다.

현재 ROM의 전체 debug 메뉴는 표시·이동·toggle·닫기 요청 수준에서 연결됐다. 전체a370 상태 머신, 다른 자식 콜백, BIOS 전환 및 최종 픽셀/타이밍은 남아 있다. 일부 연결 성공을 전체 목표 완료로 기록하지 않는다.
