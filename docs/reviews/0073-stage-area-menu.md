# 스테이지 구역 콜백과 중첩 행 갱신 리뷰

대상: `2e6e36f` 이후 변경.

메인이9602/96c8의 상태·출력 순서와a280/9d3a의 중첩 호출 깊이를 분석하고 콜백, 이벤트 연결, 단위검사를 구현했다. gpt-6.1-sol / medium 에이전트에는 확정된 stage context 전달과 줄 위치 전달, 빌드 의존성 연결, 반복 원본 비교를 분리 위임했다.

선택 그룹107dfe와 현재 행-2를 구분했다. 좌우 입력은 선택 그룹을 바꾸고, 다시 그리기는 현재 행을 사용한다. 구역byte의ff 순환, 감소 시 count 하위byte 더하기, 이름pointer0의 포맷터/일반문자열 차이도 확인했다. 설명줄 좌표는9f12 이후 word 덧셈이고 행 좌표는9f36에서 byte 덧셈이라는 차이를 유지했다.

중첩 event6에서 콜백 진입 stack은 원래S에서20바이트 낮다. 원본a280의행그리기호출4,9e0c의레지스터저장12,9e10의dispatch호출4를 합한 값이다. context를 복사해 이 값을 전달하고, 실제 이동은 기존 navigate_menu와 일반 행그리기를 재사용했다. 별도의 유사한 선택기를 만들지 않았다.

메인 리뷰에서 원본 비교 fixture의 높이가 slot+12 목표높이에만 들어가고 slot+4 표시높이는 항상0인 결함을 발견했다. 따라서 최초 통과 보고는 중첩 그리기 증거로 인정하지 않았다. 표시높이를 수정하고 보고서에서 visible_height/target_height를 구분했으며, 보이는event6의 원본포트가 비어 있지 않아야 한다는 검사를 추가해 전체 비교를 다시 실행했다.

회귀 범위는 기존 메뉴 이동1,986조건/오류12, stage9802의1,120조건, debug2,100조건이다. 전체Python55개/C++테스트와 새 구역 순환·중첩 포인터·실패보존 단위검사도 통과했다. 수정된 area 비교3,584조건도 통과했다. 보이는event6의768조건에서 실제107..408개 포트쓰기를 비교했으며, report에visible_height를 별도로 기록했다.

구분선 그리기와 부모다시그리기의 context 전달은 남았다. 보이는 구분선을 포함하는958a전체메뉴를 검증한 것으로 주장하지 않는다. API의 줄 전달은 구현했지만 원본 비교 report의 주장 범위는 전체RAM/포트/A2/외부점프이며 전체CPU레지스터는 아니다.
