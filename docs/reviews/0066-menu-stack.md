# 메뉴 스택 추가 리뷰

대상: `edc6c99` 이후 메뉴 스택 추가/하위 리소스/문자 줄 위치 반환 변경.

메인 에이전트가 a0a0..a1e0, 9f36, 3918, 9b58/9e1a 및 부모 콜백의 자식 참조를 확인했다. 다음 동작을 보존하도록 설계했다.

- 새 head를 먼저 기록하고 새 슬롯 width를 0으로 두어 부모 다시 그리기의 가림을 방지한다.
- 부모는 비활성 색으로 그리며 그리기 중 slot+8 변경을 보존한다.
- 새 슬롯의 높이 하위 byte 및 기존 renderer/input/current를 유지한다.
- 테두리와 문자 출력이 남기는 D3 줄 위치를 새 메뉴 측정에 전달한다.

서브에이전트의 슬롯 설정 공유와 문자 줄 위치 반환 코드를 메인 에이전트가 diff로 검토했다. 기존 첫 초기화 API의 최종 RAM 동작을 유지했고, 선택적 줄 위치 출력은 성공 때만 기록된다. 원본 무한/잘못된 반환 경로를 성공 처리하지 않으며, 스택이 가득 차면 오류로 거절한다. 단계별 상태는 사본에 구성하여 부모 출력 후 새 메뉴 오류에서도 RAM/출력을 보존한다.

검증 초안의 `l` 제어 인자를 16-bit 주소처럼 사용한 부분을 발견했다. 실제 x/y byte 형식으로 수정한 뒤 원본 실행과 비교했다. 이는 프로덕션 코드를 합성 테스트에 맞춘 변경이 아니다.

검증:

- 네 MS5D descriptor를 C++ `check_menu`로 읽어 manifest의 모든 필드/항목과 일치 확인.
- `verify_menu_stack.py`: 원본377조건의 전체RAM/순서 있는 포트 출력 일치, 잘못된 요청14조건 출력 파일 미생성.
- `verify_menu_init.py`: 기존 첫 초기화378조건 전체RAM 일치.
- `analyze_menu_text.py --cpp`: 기존 전체 메뉴288조건 회귀 통과.
- `make all test`: 전체 통과. C++ 단위 검사에 late failure 롤백/줄 출력 보존/스택 경계 포함.

아직 부모의 event3 콜백 디스패치에서 push_menu로 자동 연결하지 않았다. 하위 메뉴 콜백의 동적 출력과 일반 flags, 전체 a370 상태 전환, CPU 사이클/화면 픽셀 동등성은 다음 작업이다. 리소스 추출과 슬롯 추가의 검증을 전체 메뉴 시스템 완료로 취급하지 않는다.
