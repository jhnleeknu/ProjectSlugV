# 인터럽트 경로 분석과 사운드 큐 소비 리뷰

대상 기준 커밋: `d665cf3`.

메인이 c8c와3cac 및48156/3af8/3ac8의 원본 명령을 확인하고 의존성을 분리했다. 전체 인터럽트를 신호 카운터 하나로 대체하지 않으며, 먼저 실제 c8c 진입/반환 근거와 사운드 소비 구간을 확보했다. gpt-6.1-sol / medium에는 원본 interrupt 실행 분석, CLI와 소비기 원본 비교를 나누어 위임했다.

`service_sound_queue`는3cb2..3d38을 구현한다. status 저장, 명령3 우선 처리, status1의 조기 반환, 명령7f 우선 처리와 일반 큐의 연속 중복 합치기를 순서대로 보존한다. status1은f003.bit7을 남긴다. 비어 있지 않은 큐의 유효 인덱스는0..127이며, 잘못된 사용 인덱스는 앞선 변경까지 취소한다. 사용하지 않는 인덱스는 우선/빈 큐 경로에서 검사하지 않는다. 원본의 범위 밖 주소 읽기나 비종료 상태를 정상 큐로 정규화하지 않는다.

소비기 원본2,575조건의 전체RAM과2,394개 사운드 포트 쓰기가 일치했다. 모든status/command byte, 중복 길이1..127, 링 경계와 우선순위 승계를 포함한다.14개 실패 조건은 출력을 보존했다. 원본ROM 불변과 정확한1회 status 읽기를 확인했다.

별도c8c 분석은5,632개 진입 조건과864개 제한된 전체 반환 조건의 전체RAM/포트를 기대값과 비교했다.4개 의존 함수 경계는 원본 그대로 해당 주소까지 실행하고 첫 명령 전에 멈췄다. 이 결과는 C++ 전체인터럽트 동등성 검증이 아니다. 원본 코드 패치나 fake helper return은 사용하지 않았다.
