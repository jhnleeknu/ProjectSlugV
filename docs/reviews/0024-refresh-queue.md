# 큐 단위 갱신 통합 리뷰

대상:5ec8a97 이후 변경. 이전 turn은 역방향 emission 구현·원본 검증·커밋으로 진척이 있었다.

메인 에이전트는 원본0x16cfa와 정리 helper를 읽어 큐·영역·ready·방향 모델을 만들고 원본 CPU72조건과 비교했다. 확정 모델의 C++ 구현을 서브에이전트에 위임한 뒤 diff/CLI를 리뷰하고 MS5C 연결·회귀 테스트·96조건 확장 검증을 수행했다.

발견·수정: record X word를 U로 바꿀 때 하위6bit를 버릴 수 있었다. 원본 생성기에서 성립하는 하위6bit=0 조건을 검증하고 오류 처리한다. 잘못된 두 번째 레코드에서 실패하더라도 첫 레코드의 임시 명령·RAM 변경이 호출자에게 유출되지 않는지 테스트했다.

검증:
- make all test: Python55개 및 C++ 전체 테스트 통과.
- analyze_sprite_refresh_queue.py --cpp:96조건의 원본64KiB RAM 및 모든 비디오 쓰기 일치. 두 영역·양방향·ring wrap·ready 유무·20개 레코드 슬롯 소진 포함.
- API 입력 오류, 누락/중복 리소스, malformed payload, X 정렬, idle no-op 및 실패 시 상태 보존 확인.
- CLI는 모든 입력·출력·리소스 경로의 이름/실제 inode 중복을 거부하고 데이터 검증 후 출력을 연다. 파일 I/O 실패 시 두 출력 파일의 원자적 교체를 보장하는 API는 아니다.

한계: 분기표 첫 번째의 일반 단일 직사각형만 처리한다. bank 장치 쓰기는 리소스 로더로 대체하며 원본 비교는 최종RAM bank shadow 및 비디오 포트 범위다. CPU flags·IRQ·실시간·전체 게임과 동일하다는 주장은 하지 않는다.
