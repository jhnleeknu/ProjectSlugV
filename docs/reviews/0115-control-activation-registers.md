# 요청·비활성 컨트롤러의 D1 반환 리뷰

대상 기준 커밋: `4e6b024`.

메인이 원본9086..9134, 비활성9136..91be, 313c, 공통92a8..92cc의 명령을 확인했다. D1 byte 변경은90c8/90cc에만 있고, 이후 요청 필터와 무관하게 남는다. pending 또는 요청 게이트 우회는 전체 D1을 보존한다. 해당 경로의 D3는 변경되지 않는다. 선택적 API 인자로 기존 호출을 유지했으며 활성 컨트롤러 전체 반환을 구현했다고 주장하지 않는다.

- `make -j3 all test`: Python73개 및 C++ 전체 검사 통과. 경고 없음. 로그 `artifacts/control_activation_registers_build_test.log`.
- 추가 단위 검사는 필터 후 요청0에서도 D1이 바뀌는 경우, pending/게이트 우회 및 오류의 D1 보존을 확인한다.
- `.venv/bin/python tools/verify_control_activation_registers.py`: 원본3,141조건(요청1,088/비활성진입2,053), 오류25조건 통과. 전체RAM, 반환byte, 전체D1, 원본D3 보존 및 포트 부재를 비교한다.
- 활성화→f5a 연속5조건에서 CLI가 반환한 status/D1과 보존된 입력D3를 다음 API에 공급했다. 변경된D1을 실제 전달하는 pending0조건을 메인 리뷰에서 추가했다. 네이티브 CPU 문맥을 유지하며 전체RAM/레지스터/순서 있는 포트1,305개를 비교했다.
- 정규 `palettes.ms5p` 바이너리를 후속 처리에 사용한다. 원본 고정ROM과 매핑된 팔레트은행(PVC레지스터 제외)이 불변임을 확인했다.
- 보고서 SHA256 `d64d7e73667af2b9180ce1f221be85f52195c4bed4419ac4def5ce02394881c6`.

CLI의 잘못된uint32, RAM크기, 활성상태, 입력/출력 동일경로·하드링크·심볼릭링크 거절 시 기존출력이 보존된다. 원본의 다른 scratch레지스터와SR, 활성대기·메뉴의전체D1/D3, 연속메인루프전체는 이번 범위가 아니다.
