# 선택 그룹 카탈로그와 상태 helper 리뷰

대상: `5cfc38f` 이후 변경.

메인 에이전트가474e2/47540/4823a..48294를 분석했다. 선형 디스어셈블에서4827c의 padding과4827e 진입점이 섞인 것을 확인하고 실제 호출 진입점에서 다시 디코딩했다. 데이터 포인터 표를 명령으로 취급하지 않고19개 포인터를 읽어 원본 경계를 확인했다.

서브에이전트의 C++ 로더/조회 코드에서 payload 시작은 length word 다음, 이름은 payload+18임을 확인했다. signed length의 양수 범위, 짝수 길이, 마지막 종료 word, 고정 ROM 주소, 큰 stage의 group0 보정, 큰 area의0 반환을 검토했다. 첫18바이트는 아직 의미가 확인되지 않아 원시 데이터로 보존한다.

C++ query CLI에 불필요한 파일 helper가 복사되어 생긴 컴파일 오류를 제거했다. 형식 오류가 있는 마지막 그룹에서도 이전 카탈로그를 보존하는 테스트와 query 출력값 보존을 추가했다.

검증:

- 원본19그룹·59레코드·index·manifest 모두 byte 수준 일치.
- 원본/C++ 조회450조건 count/record/name 일치.
- 원본/C++ 상태변경272조건 전체64KiB RAM 일치.
- 잘못된 레코드/소스 주소/상태 입력의 오류 및 보존 검사, `make all test` 통과.

실제 스테이지 로더나 전체 메뉴9602/9802를 구현한 것으로 주장하지 않는다. 다음 단계에서 이 공유 catalog/helper를 콜백과 연결하며 원시 header의 참조 대상을 분석한다.
