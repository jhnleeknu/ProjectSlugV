# 표시 준비·갱신 연속 경로 리뷰

대상:ecef0c8 이후 변경. 이전 turn은 사전 안정 정렬의 구현·원본 검증·커밋으로 진척이 있었다.

메인 에이전트가 준비 루틴을 검증된 정렬·emitter와 연결하는 모델을 도출하고 원본96조건을 먼저 비교했다. C++ 구현을 서브에이전트에 위임한 뒤 source/header/CLI를 읽고 API 테스트와 준비→갱신 연속 비교를 추가했다.

- 준비 emitter 제한은 반대편 cached cursor이며 물리 영역 경계와 구별한다. 초기 현재 cursor만 물리 경계에서 시작한다.
- ready는byte전체0xff이며 방향/read cursor를 바꾸지 않는다.
- 비동기 대기는 구현하지 않고 synchronized-consumer 계약을 명시한다. 원본과 다른 입력 거부 동작은 지원 범위의 경계이며 원본 대기를 복원한 것으로 취급하지 않는다.
- 지연 개수와 일반 끝/생산 끝 일관성을 확인하고255개 초과를 거부한다.
- 잘못된 두 번째 레코드/리소스·X정렬·불일치 cursor의 오류가 RAM/출력을 부분 변경하지 않는지 테스트했다.
- 비디오 출력0개에서 CLI는빈파일을 안전하게 쓴다. 모든 입력을 검증한 뒤 출력 파일을 열지만 I/O 실패의 다중파일 원자성은 보장하지 않는다.
- make all test 통과.
- analyze_sprite_prepare_queue.py --cpp:96개 준비 결과와96개 연속 갱신 결과가 각각 원본64KiB RAM·모든 비디오 쓰기와 일치했다.

아직 일반 직사각형 분기이며 전체 게임의 입력/시간/IRQ/픽셀/사운드 동일성은 미완료다.
