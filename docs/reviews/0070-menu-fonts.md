# 혼합 글꼴과 스테이지 이름 표시 리뷰

대상: `4e6e369` 이후 변경.

메인 에이전트가 e84c8..e8734와 e89da 진입점을 다시 디스어셈블하여 68/6b의 표 선택, direct의 결합문자 이전 분기, font30의 결합문자 이후 분기를 확인했다. C++ 변경 및 합성 오류 검사는 메인이 담당했고, 리소스 패킹과 반복 비교 확장은 gpt-6.1-sol / medium 서브에이전트가 담당했다.

패커의 새 표 범위1024바이트와 기존6b 출력 유지, verifier의 원본3918 실행·ordered port 폭 마스킹·D3 비교 및 실제59이름의 경계 추출을 검토했다. 원본 명령이나 콜백을 stub으로 치환하지 않는다. 성공한 과거 결과가 남지 않도록 verifier가 이전report/output을 제거한다.

검증:
- 혼합 글꼴704스트림의 원본/C++ 출력 및 줄 위치 일치. 실제59이름 포함.
- 결합 MS5D payload1024바이트와 header/CRC가 원본과 일치.
- 정상68 단독표, 없는표/미지원style의 트랜잭션 보존, direct/font30 소비 차이, 주소 순환 단위검사.
- `make all test` 및 기존debug메뉴2,100조건 회귀 통과.

폰트30은 @ 처리보다 먼저3650을 호출한다. 이를 lookup 글꼴의 @ 문법과 공유하지 않았다. 68/6b 표 검사도 글리프별로 하여 동적 font switch 뒤 없는 표의 범위외 접근을 방지한다.

전체 포맷터3a70, 스테이지 콜백9602/9802와 전체메뉴frame은 남았다. 이번 구현을 스테이지 실행 완료라고 부르지 않는다.
