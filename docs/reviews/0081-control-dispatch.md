# 통합 제어 진입과 호출자 분석 리뷰

대상: `ed13713` 이후 변경.

메인이9136의 분기 우선순위와 비활성 경로의 D0/D3 계약을 원본에서 재확인하고 통합 API/단위 검사를 구현했다. gpt-6.1-sol / medium에 CLI·Makefile 연결, 연속 원본 비교, 호출자 helper 목록화를 위임했다. 메인이 실제 diff와 검증 코드를 검토했다.

통합은7df0을 먼저 검사한다. 비활성일 때 오래된7dee를 무시하고 수락 경로를 실행하며, 이후 활성 호출에서만7dee로 대기/열린 메뉴를 선택한다. 사용하지 않는 리소스와 스택까지 일괄 검증하지 않는다. 상태는 기존 signed D0 계약을 유지한다. 비활성 경로의 결과와 포트는 수락 완료 뒤 교체하며, 활성 경로는 검증된 트랜잭션 API에 위임한다.

원본 비교835조건 중258프레임은4개 활성화→누름 반복→메뉴/자식 조작→전체 종료→재활성화→두 번째 종료 시퀀스다. 전체RAM과D3를 이어서 사용한다. 원본9136 및 실제 메뉴/종료/stage callback hook을 기록하고 모든 RAM/D0/D3/102,635포트가 일치했다. 오류 fixture에서도 실제 메뉴 시작 결과를 사용한 뒤 마지막 root pop 이후 콜백 오류의 출력 보존을 검사한다. 보고서 SHA256: `123e0774c0313c8fc741e753f3155004aeeb381c9f8ad06adddc3c60371b550e`.

메인이f5a의 상태 소비를 별도 원본 실행 도구로 분석했다. 새 상태의 하위 byte만 검사하고 이전 상태와 조합하여 video 조회/복구, 효과 저장/복구 및 카운터 경계를 결정한다.512조건에서 실제 helper 순서와 선택 상태를 검사했으며,ec4 루프128회/trap 직전192회/rts192회를 관측했다. 전체RAM 해시를 전체RAM 독립 모델 비교로 표현하지 않는다. 팔레트 준비는 원본pending gate로 연기하고trap/ec4 이후 실행은 범위 밖으로 명시했다. 보고서 SHA256: `33eb12994474a8dd3ea8ab035be5e35dc83bbb5c6400e1585b18471509a1d120`.

검증: `make all test`(Python61개/C++ 전체), `tools/verify_control.py`, `tools/analyze_control_caller.py`, CLI 숫자/출력 별칭 거절 smoke 및 `git diff --check` 통과. 빌드 로그는 `artifacts/control_build_test.log`다.
