# 메뉴 이동과 지정 선택 리뷰

대상: `3a344fe` 이후 메뉴 이동 구현 및 행 출력 공유 변경.

## 검토

- 메인 에이전트가 원본 a216..a29a 및 9d3a..9e18을 읽고 검색 조건, byte 순환, 이전/새 행 출력 순서와 마지막 event 0 기록을 확정했다.
- 서브에이전트의 단일 행 API와 전체 메뉴 출력 리팩터링을 diff로 검토했다. 전체 메뉴의 기존 검증 조건과 슬롯+8 갱신을 유지하고, 단일 행 API는 보이지 않는 행의 조기 반환 및 제목 주소 0 경로를 허용한다.
- 검색 결과만 출력하는 방식 대신 원본의 두 번의 그리기를 연결했다. 같은 인덱스 선택에서도 중복 출력을 생략하지 않는다.
- 무한 검색, 잘못된 count/기존 index, 미지원 콜백을 성공 처리하지 않는다. 새 행 오류 전에 이전 행 출력이 생성된 경우도 외부 RAM/쓰기 목록에 반영되지 않음을 테스트했다.
- Makefile 검토에서 테스트 의존성이 잘못된 타일 테스트에 추가된 것을 발견하여 최상위 test 대상으로 수정했다.
- 비교기는 원본 프로그램 명령을 수정하지 않는다. 합성 descriptor/문자열만 별도 고정 ROM 데이터 창에 배치한다. 원본은 실제 event-5 콜백까지 실행한다.
- 검증 초안에 포함된 보이는 비영 flags 사례는 현재 명시된 flags0 구현 범위를 벗어났다. 이를 정상 성공으로 주장하지 않고 거절 검사로 분리했다. 보이지 않는 행의 비영 flags 우회는 원본과 성공 비교한다.

## 검증

- `make all test`: Python 55개 및 전체 C++ 테스트 통과.
- `tools/analyze_menu_text.py --cpp`: 기존 전체 메뉴 288조건의 RAM/순서 있는 포트 쓰기 일치.
- `tools/verify_menu_navigation.py`: 실제 메뉴와 합성 데이터 1,986조건의 전체 RAM/포트 일치, 잘못된 요청 12조건에서 출력 생성 없음.

## 남은 범위

일반 event 디스패치, 다른 descriptor flags/콜백, 보이는 이전 구분선 출력 및 a370 전체 프레임은 아직 미구현이다. CPU 레지스터/사이클, 인터럽트 및 최종 화면 픽셀 동등성은 이 검증의 주장이 아니다.
