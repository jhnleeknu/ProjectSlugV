# 사운드 word 큐와 타이머 실행 근거 리뷰

대상 기준 커밋: `47e47ee`.

메인이 원본3af8/3c08의 필터, 한 슬롯 교환, overflow와 byte 대기 시 스택 보관 값을 해석했다. C++ 구현/단위 검사/통합을 직접 수행하고 gpt-6.1-sol / medium에 CLI, 원본 비교, 별도48156 실행 분석을 분리 위임했다. 모든 산출물의 실제 코드를 검토했다.

생산자는 overflow에서 head를 먼저 전진시키고 배출자는 완료 시에만 head를 저장한다. 재개 상태에는 상위/하위 byte 단계, 보관된 low/cursor와 기존 byte 생산자의 캡처 상태를 넣었다. live head와 이미 읽은 word 내용을 다시 참조하지 않는다. 완료 상태는 전부0이며 오류는 해당 호출 전체를 취소한다. 늦은 live tail 오류가 이미 쓴 byte까지 되돌리는 것을 단위 검사와 CLI에서 확인했다.

검증 리뷰 중 원래 일부 fixture가2000 이상이라 생산자에서 걸러지는 문제를 발견했다. 허용 명령으로 바꾸고 실제 enqueue 대기와 하위 byte 대기 도달을 assert했다. 필터 행렬은 임의 추림을 제거하고16개 경계 명령×128개 플래그 조합을 전부 실행했다. 원본 CPU 문맥과 스택을 보존한 재개를 비교하지만 호스트의 명시적인 큐 변경을 자연적인 장치 동시 실행으로 간주하지 않는다.

별도48156 원본 분석은65,536개 timer word를 전부 검사했다. signed 비교, word wrap, MOVEQ와 MOVE.W의 D0 상위 차이, 전체RAM과 정확한 생산자 진입 경계를 확인했다. 이것은 C++ 타이머 구현 검증이 아니며3af8 실행 전에서 중단한다.

`make all test`: Python73개 및 C++ 전체 통과. 로그: `artifacts/sound_word_build_test.log`. `git diff --check` 통과.

48156과3cac 연결, 전체 interrupt와 실제 재개 스케줄링, Z80/오디오 시간축 및 전체 게임 부팅은 미완료다. 전체 목표는 active다.
